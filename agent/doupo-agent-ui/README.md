# 斗破同人 Agent · 酒馆扩展

一个跑在 SillyTavern 里的文字游戏总控。默认由酒馆生成正文，扩展做生成前注入、生成后各域记账，并把台账保存到当前聊天；扩展自行编写和投递正文的手动回合管线是默认关闭的旧链。能力通过 `doupoAgent` 命名空间提供。

## 可选旧链：手动结算一轮（默认关闭）

1. **解析**：把玩家消息交给模型，得到结构化意图（类型、任务、明确行动、效果、天数）。
2. **授权**：分类器判断这轮是闲聊、查询、明确行动还是时间推进；行动必须由玩家自己说清楚才放行。
3. **计划**：路由器只把任务分给白名单模块（资料查询 / 行动结算 / 世界推进 / 开放世界推进），越权请求直接拒绝。
4. **六阶段管线**：`classify → plan → gather → adjudicate → compose → validate`，每阶段有超时与输出上限，总预算 90 秒。
5. **两道门**：质量门核对作用域、字段登记、唯一写入者与玩家授权；叙述门核对正文里的每条事实是否有依据。
6. **两段式提交**：先把正文发进对话并确认消息可见，再提交状态；提交成功后状态版本 +1，并写入 `chatMetadata`，刷新页面后仍在。

以上只描述 `ui.legacyTurn` 打开后可用的旧回合管线：前置门失败不提交状态；正文确认后保存不确定时会返回 `save_uncertain`，不能承诺正文一定不存在。它不是下面默认的酒馆正文生成与后台台账链。

## 原著设定怎么进提示词（默认路径）

正文默认交回酒馆自己生成，扩展只负责在生成前把“这一轮真正需要的原著条目”塞进提示词：

1. **建索引**（启动时、切聊天时自动跑）：`setting.worldbook` 填世界书名，扩展用 `loadWorldInfo` 只读它，按 `comment` 里的「题名（类别-名字）」拆出类别、名字、别名；卷号来自 `世界书/tools/build-volume-index.mjs` 生成的 `narrative/volume-index.generated.js`。
2. **发目录**：当前卷的条目按 `uid|类别|标题|摘要` 排成目录（故事线只给标题，前情只给标题、不铺后续卷）。
3. **模型点名**：一次 `generateQuietPrompt` 静默生成，只回 JSON `{"need":[{"uid":11,"why":"..."}],"no_match":false}`；`jsonSchema` 一并传给酒馆。
4. **脚本取货**：uid 必须在目录里，越界丢弃，最多 6 条；按 `injectionBudget` 预算裁到整条或摘要。
4½. **卷外兜底**：目录里没有、但模型判断必须用到的，它把名字写进 `"lookup"`；脚本全库搜（标题、key），把候选带卷号列出来再问它一次，只接受候选里的 uid。没给名字或全库搜不到，就不发这次额外调用。
5. **注入**：`setExtensionPrompt(key, text, IN_CHAT, depth=0, scan=false, SYSTEM)`，生成结束或中断时清空；文字不进聊天记录、不写世界书。
6. **对账**：正文里出现“没注入过的条目名”记一条 `unapproved_setting_use` 审计，不拦生成。

世界书侧的分工是硬边界：**启用中的条目仍归酒馆原生注入**（28 条体系 + 1 条原著分卷汇总），插件导入时会把它们跳过，只接管关闭的 1132 条明细——同一段设定永远只走一条路。`node 世界书/tools/worldbook-disable.mjs --write` 负责把明细全部关掉，只留启用层；`node 世界书/tools/add-volume-index-entry.mjs --write` 会按 `原著分卷/卷NN_标题.txt` 重建那条常驻的《原著分卷汇总》（constant、order 100）。两个脚本都默认干跑，写前留带时间戳的备份。

插件只读不写：注入走 `setExtensionPrompt`，从不调用 `saveWorldInfo`，世界书的启用状态、文件和酒馆其它功能都不受影响。

设置页「原著设定」里的对应关系：检索库状态显示已索引条数、七分类分布、缺卷号条数和当前卷目录行数；「世界书名称」可手填，点“扫描可选世界书”会尝试列出酒馆里的世界书名字（酒馆版本不支持时回退为手填）；改动名称后会自动重同步索引，也可点“从世界书导入”手动重建。下面的「注入通道」控制是否注入、插入深度和最大字数。

手动“结算这一轮”的旧链路仍在，但默认关闭（`ui.legacyTurn`），避免和酒馆主生成抢正文。

选条提示词（模型看到的 system 指令）写在设置 `prompt.select`：留空用内置默认，`MAX_PICKS` 会替换成当前上限，改完下一轮生效，不用重启。

当前卷有两种来源：面板“当前剧情卷”填了就是手动锁定；留空时走自动判定——模型在选条 JSON 里顺带给的 `volume`，加上“正文里出现故事线标题原文”这一条兜底，取较大值，且一轮最多前进一卷。判定结果写回 `facts.currentVolume`，运行状态卡会显示当前卷、来源和自动值。

## 世界事件系统（world/）

**LLM 决定脚本执行**是主路径：生成结束后，扩展发起一次独立的模型决定调用——模型读**最近聊天 + 相关世界书条目 + 世界台账**，输出严格 JSON（`{"note":"…","ops":[…]}`，附 jsonSchema 约束），脚本逐条校验执行，结果（模型说明 + 每条操作 ✓生效/✗被拒）呈现在设置页「模型决定」卡里。

1. **决定调用**（`world/world-decide.js`）：默认提示词 `WORLD_DECIDE_PROMPT` 写死事件取材与输出契约；设置页「模型决定」卡的**决定提示词**框打开就显示当前生效的完整正文（留空时自动铺入内置默认，所见即模型所收），直接改、清空则恢复跟随默认，`world.decidePrompt` 存改写版。世界书侧输入按本轮聊天去 facts 索引匹配条目（`uid|类别|标题|摘要`，上限可设），不铺全文。模型与温度可在设置里单独覆盖（独立接口模式生效；酒馆连接沿用当前模型）。`world.decideAuto` 关掉后退回"只认正文指令块"的降级模式（指南随现状注入，回复末尾 ```world 代码块照旧解析）。
2. **脚本执行**（`world/world-runtime.js`）：越界数值、未知操作、超长文本只拒绝不炸；同楼重 roll 先撤销上一版指令（含被它到期了结的事件）再落新账。
3. **操作集**：`advance`（天/分钟）、`setClock`、`addEvent`（scope near|world、title 短标题必写≤16字、basis 依据必写、weight minor|major|rumor、days 有效天数≤90）、`resolveEvent`、`pinEvent`、`setInfo`（weather/location/era/reputation 名声/wanted 通缉度）、`addTask`（title 必写/detail/basis/days 时限）、`completeTask`、`deleteTask`、`updateTask`、`setFaction`（势力名/stance 敌对|警惕|中立|友好|同盟/动向/依据，按名字 upsert）、`deleteFaction`、`setPerson`（人物名/态度/依据）、`deletePerson`、`setTension`（世界氛围 calm 平静|rising 升温|storm 风波）。事件可带 `location`（事发地点）；决定规则要求事件符合所在地特征（魔兽山脉是兽袭与药草，帝都是权贵与阴谋），氛围决定每轮投放事件的频率与烈度。任务规则：玩家承诺或接下的事、人物托付、剧情给出的明确目标才立任务；任务栏会注入给正文模型，完成后 completeTask、作废 deleteTask、进展 updateTask。势力与人物只在剧情真的接触或关系变化时更新，不照世界书预登记。季节为推导值：一年 360 天四季轮转，注入的时钟行与面板都显示季节，环境描写要跟季节对上；固定大会/仪式用 addEvent 带未来 day 登记成预定事件（注入标「预定：第X天」）；advance 一次跨 7 天以上（闭关、赶路）时，决定模型必须补 1-3 条跳跃期间的动向事件，出关时世界不是原地等你。`advance`（天/分钟）、`setClock`、`addEvent`（scope near|world、title 短标题必写≤16字、basis 依据必写、weight minor|major|rumor、days 有效天数≤90）、`resolveEvent`、`pinEvent`、`setInfo`（weather/location/era/reputation 名声/wanted 通缉度）、`addTask`（title 必写/detail/basis/days 时限）、`completeTask`、`deleteTask`、`updateTask`。任务规则：玩家承诺或接下的事、人物托付、剧情给出的明确目标才立任务；任务栏会注入给正文模型，完成后 completeTask、作废 deleteTask、进展 updateTask。
4. **事件取材规则**（提示词里写死，可改写）：事件从聊天记录里有依据地长出来，题材不拘（市井琐事、势力动作、传闻），basis 必须写清从哪来；没有依据不记，不把世界书里的原著桥段照搬成事件。**rumor=传闻**：未证实消息，正文不得当事实写，查证后 resolveEvent 了结并另记真相或戳穿。**机遇与危机**（拍卖会、药草成熟、仇家寻上门、势力清洗）属于世界主动投放的 major 事件：偶尔来一件、必须有依据。**名声/通缉度**只在剧情真有对应行为时更新，注入的现状行会显示。
5. **到期清扫**：时限事件推进过线自动了结并留流水；注入列表显示"剩 N 天"。
6. **持久化**：台账整体存 `chatMetadata.doupo_agent_world`，随聊天保存；切聊天自动恢复。
7. **面板**：全部集中在设置页「世界运转」——世界时间与现状卡（时钟、手动推天/设钟，时期/所在地/天气/名声/通缉度五个信息字段手动设定）、双栏事件（剩余天数、传闻标记、了结/置顶）、**任务卡（进行中/已逾期/已完成全部列出，详情完整展示，每条可手动完成/删除，也可自己接任务）**、手动登记事件（范围/分量含传闻/依据/有效期）、模型决定卡、指令指南与决定提示词改写、指令流水。手动操作与模型决定走同一套校验。

上限保护：单批最多 12 条操作（解析截断 12、运行时执行上限 12，已对齐）、事件单栏最多 60 条（先清已了结、再清未置顶最老的，置顶永不清理）、事件文本 300 字、信息字段 80 字、单次推进最多 365 天；同栏同文的进行中事件不重记（`duplicate_text`）。


## 悬浮球（`host/orb-hud.js`）

屏幕右侧挂一颗小球；点一下，球竖直拉伸成一根胶囊长条（顶上和底部都是半圆），条上从上到下排十一个图标：总控 ⌂、世界运转 ◌、纳戒 ◉、记忆存储 ✧、人物簿 ☰、冷藏推进 ❄、世界影响 ⌁、原著资料 ▤、数据镜像 ⇄、运行日志 ✎、开放世界 ◈。点图标弹出对应功能的**只读信息窗**——世界运转有时钟/季节/时期/所在地/天气/名声/通缉度/世界氛围、双栏事件、势力动向（敌对排前）、相关人物与任务；纳戒有身份/境界/金币计数与称号、功法、斗技、行囊、配方、炼制中、目标七份清单；记忆存储有大记忆/小记忆两栏（关键排前、带引文/关联/标签）；数据镜像显示数据库桥接（12 张桥接表）与 MVU `stat_data.斗破纳戒` 的同步现状；运行日志把审计流水倒序列出（事件与结果都翻成中文）；人物簿只有档案计数与人物一览（好感刻度照搬）；其余各窗同理。没有按钮、没有输入框，改状态仍走设置面板。

交互：再点同一个图标关信息窗（长条保留）；点球或按 Esc 或点页面其他地方收起整条；换图标直接换窗。**人物簿一览的每一行可以点开**：在信息窗外侧弹出一张只读小档案卡（抬头好感、角标在场/重要/位置/身份、按组只列有内容的字段、最近三条经历与流水），点同一个人收起，Esc 先收卡再收长条，回合事件到达时小卡跟着重画。信息窗在回合状态事件到达时自动刷新。图标多到超出屏幕时胶囊会被视口高度截住、可直接滚动（滚动条隐藏）；设置页「总控」的**显示悬浮球**开关（`showOrb`，默认开）控制显隐；配色跟随界面颜色三主题。

分工：`host/orb-hud.js` 是纯逻辑（图标清单 `ORB_ITEMS`、展开/收起状态机 `createOrbState`、十一个信息窗的数据投影 `buildOrbPanels`），全部输入可为 undefined、不碰 DOM，只从纯逻辑模块借几张现成标签（季节 `seasonOf`、势力立场/世界氛围、记忆标签）；挂载、动画与事件接线在 `index.js`（`mountOrbHud`/`syncOrbHud`/`collectOrbData`），样式在 `host/style.css` 的「悬浮球」段。哪路运行时没就绪，对应的窗就显示「暂无」，不会报错。`dev/orb-smoke.html` 是离线冒烟页：静态服务器打开后自动激活扩展并灌演示数据。


## 目录

- `core/`：协调器、回合管线、六阶段实现、编排器、状态库、提交恢复、质量门、数据合同、审计与账本。
- `world/`：世界事件系统——台账运行时（时钟/双栏事件/指令校验）、指令解析与注入文本、随聊天的存取。
- `memory/`：记忆存储——小记忆/大记忆两层（按需召回，永不过期）的台账运行时、召回注入、指令解析、决定提示词、随聊天的存取。
- `self/`：纳戒——主角自身状态与随身之物的运行时（身份/境界/功法/斗技/行囊/制作台/目标）、指令解析与注入文本、决定提示词、随聊天的存取。
- `narrative/`：事实库、正文核验、历史事件适配与恢复。
- `request/`：请求分类、路由、行动结算、世界推进。
- `npc/`：NPC 计划、决定守卫、冲突协调与提交门禁；`npc-ledger.js` 人物簿（档案与好感台账）、`npc-recorder.js` 生成后的记录员提示词与补丁解析、`npc-cold-runtime.js` 冷藏选择/日期游标/预览台、`npc-cold-recorder.js` 冷藏推进提示词。
- `host/`：宿主能力预检、设置与存档、模型客户端、消息投递、状态持久化、控制台视图与样式、数据库桥接（纳戒/记忆 ↔ 龙血玄黄·数据库）、悬浮球纯逻辑（`orb-hud.js`）。
- `index.js`：浏览器入口；`run-tests.mjs`：递归运行全部模块测试；`demo-turn.mjs`：离线跑完整一轮。

## 人物簿（`npc/npc-ledger.js`）

正文落地后，人物记录员做一次独立小调用：读最近两楼正文 + 人物簿索引 + 命中的世界书条目，只回一张补丁清单（`{"人物":[{"姓名":"萧炎","好感":3,"理由":"挡了一掌"}]}`），合并交给脚本——好感只记增减，**单次最多 ±10**（模型写 +95 也只记 +10，跨轮累加、±100 封顶），流水只追加、改一次版本号加一、认不出的字段原地忽略、坏 JSON 直说不动档案。下一次生成前按“在场/不在场 × 重要/不重要”四象限挑人写进正文提示词：在场且重要给全字段，其余给一行，又不在场又不重要就不注入；超预算从最不重要的人开始降级成一行，不硬截断。档案跟着聊天存 `chatMetadata['doupo_agent_npc']`，设置页「人物簿」可开关、调节奏、看档案、手动记账；名单里点「改在场 / 改不在场」「标重要 / 降普通」可直接纠正四象限，下一轮照新档位注入。记录员这一路小调用的连接（跟随酒馆 / 自定义接口地址、密钥、协议）和生成参数（模型、温度、输出上限、top_p、两个惩罚项）全在「记录员参数」里填，填 0 或留空即沿用全局。

**按世界书重抽**：正文只写了半截的人，可以点「按世界书重抽：只填空着的字段」——脚本按姓名/别名/称号去原著设定库逐条找，只把还空着的字段补上，正文记下的身份、好感、流水一律不动；“设定库里没找到”会点名报出来。单个人行里的「重抽」是覆盖式重写：身份/外貌/身体/性格/资产按世界书重来，好感、流水、态度、处境、秘密不动（弹窗确认后执行）。

**玩家处境接线口**：记录员要知道“玩家此刻在哪、什么境界”才分得清“萧炎赶来”是赶去哪。这项不自己猜，等外部接：`doupoAgent.npcLedgerSetPlayerContext(() => ({ location: '萧家后院', realm: '斗者三星' }))`，没接就不注入这一行。

**冷藏推进台**：在人物名单左侧勾选需要“留在后台生活”的人，时间只看世界台账当前是第几天。点“扫描需要推进的人物”后，脚本只挑姓名/别名/称号确实出现在新事件里的冷藏人物；模型只收到原档案、实际日期差、相关事件和最近正文参考，先生成草稿。草稿会停在面板里，逐份点“确认写回人物簿”才调用人物簿的唯一写入口；点“放弃”不会改档案。第一次勾选只建立当天基线，不会把过去的事件硬补给人物；同一天没有新牵连事件不会调用模型；冷藏台不会推进世界钟、不会替其他人写档、不会自动运行。冷藏状态存 `chatMetadata['doupo_agent_npc_cold']`，与人物档案分开。

冷藏推进员可在人物簿页单独设置连接、模型、温度、输出上限、top_p、两个惩罚项和提示词；默认提示词要求“只按明写依据、好感单次最多 ±10、只出 JSON 草稿”。这套参数在「人物簿」页与「模型与提示词」集中页各有一份、走同一个 `data-setting` 通道；选“跟随酒馆”时接口地址、密钥与模型名会置灰，免得以为填了会生效。

## 纳戒（`self/`）

主角自身的总账，和人物簿（记别人）、世界台账（记世界）互不重叠：身份档案（姓名/性别/年龄/种族/出身/所属/天赋/外貌）、境界与段位（斗之气→…→斗帝）、金币、称号、功法、斗技、行囊（含装备中标记，同名同类别自动并账）、制作台（已掌握配方 + 炼制进度，按世界时钟倒数、显示超期）、目标约定（主线标星、达成退场）。

1. **默认与可选通道**：`self.mvuChannel` 默认 `inline`，正文经 MVU 申报、扩展仲裁后写纳戒；改为 `independent` 才在生成结束后调用 `self/self-decide.js`，读取最近聊天/相关设定/纳戒，输出 `{"note":"…","ops":[…]}`（≤12 条）。独立模式若主回复已带申报块，会沿正文通道兜底，避免重复记账；`self.decideEnabled`/`self.decideAuto` 管独立决定启用/自动触发，关闭自动仍可手动请求。`self.guide` 与正文 `self` 指令解析是保留的兼容能力，不等于开启合并决定。`self.decidePrompt` 留空跟随内置默认；连接和喂料使用独立的 `self.decide*` 设置。
2. **操作集**：`setProfile`（八个身份字段）、`setRealm`、`setGold`/`addGold`、`addTitle`/`removeTitle`、`addTechnique`/`updateTechnique`/`removeTechnique`、`addSkill`/`updateSkill`/`removeSkill`、`addItem`/`updateItem`/`removeItem`、`addRecipe`/`removeRecipe`、`startCraft`/`finishCraft`、`addGoal`/`finishGoal`/`removeGoal`。
3. **注入**（`self/self-ops.js`）：生成前把纳戒现状写进独立注入通道 `doupo_self`，与世界、影响、人物簿、原著设定四路互不清空；超预算从目标、进行中炼制、行囊往上丢，身份与境界永远保留。
4. **脚本执行**（`self/self-runtime.js`）：越界数值、未知操作、超长文本只拒绝不炸；同楼重 roll 先撤销上一版指令再落新账；撤销恢复保留原编号且发号器同步前进；行囊扣到 0 自动移除条目。
5. **持久化**：整份纳戒存 `chatMetadata.doupo_agent_self`，随聊天保存，切聊天自动恢复。
6. **面板**：设置页「纳戒」按子页签分六页——基本信息（身份字段逐格手改、境界突破、金币、称号、流水）、功法、斗技、行囊（装备/卸下、改数量）、制作台（配方 + 开工/成丹/炸炉）、目标（立目标/达成/移除）。手动操作与模型决定走同一套校验，改完立即记进流水。
7. **所有权边界（防双写）**：世界时钟/事件/名声通缉归「世界运转」，NPC 档案与好感归「人物簿」，纳戒只记主角自己；决定提示词里同样写明不越界。

## 数据库桥接（`host/db-bridge.js` + `host/db-tables.js`）

可选把纳戒与记忆镜像到**「龙血玄黄·数据库」**（酒馆助手脚本，`window.AutoCardUpdaterAPI`）。**持久状态权威是各自的 `chatMetadata` ledger（随聊天保存的台账），数据库表和 MVU 帧不是独立真账本**：世界 `doupo_agent_world`、纳戒 `doupo_agent_self`、记忆 `doupo_agent_memory`、人物簿 `doupo_agent_npc`、冷藏推进 `doupo_agent_npc_cold`、世界影响 `doupo_agent_impact` 各归自己的运行时写入。**世界运转不连数据库**——时钟/事件/任务只跟世界台账走；旧版镜像过的三张世界表会在合并导入时从聊天模板移除。`enableDbBridge` 默认开启；关闭或未装数据库脚本时桥接调用跳过，不改变聊天台账的持久化路径。

- **表结构**（`db-tables.js`，12 张，uid 固定）：纳戒 10 张（主角档案、称号、功法、斗技、装备、天材地宝、行囊、炼丹、炼器、目标）+ 记忆 2 张（小记忆、大记忆）。桥接表的 `initNode/insertNode/updateNode/deleteNode` 都是「禁止操作。」，`updateConfig.updateFrequency=0` 配合 `uiSentinel=-1` 表示退出数据库 AI 自动填表；这是模板配置合同，不替代真实宿主验证。
- **模板自愈**：换聊天/启动时读当前聊天模板，缺桥接表就用 `importTemplateFromData` 以 `dataMode:'merge'` 补进当前聊天（每个聊天至多一次）。注意数据库脚本的 merge 导入是**整包替换**：外来表必须随包携带才不会丢；而它又按「DDL 注释 = 表头」逐列校验整包，所以导入前会把注释与表头对不上的外来表 DDL 按表头重建（`sanitizeForeignDdl`，表名/表说明/行内容/updateConfig 不动，桥接表永不改写）——外来表的行数据与结构不受影响，只是 DDL 注释被对齐；旧语义模板带 0=沿用UI 时不置新语义标记，避免误禁外来表的自动更新。
- **生成来源**：`agent/斗破Agent数据库桥接表.json` 只从 `host/db-tables.js` 的 `buildBridgeSheets()` 生成，含 12 张仅表头的空表、mate、「禁止操作。」节点与 updateConfig；小/大记忆 `exportConfig.enabled=false`，不含废弃的「已了结/了结日」列。仓库根目录执行 `node agent/doupo-agent-ui/tools/build-db-template.mjs`，写前结构自检；再用 `node agent/doupo-agent-ui/tools/docs-contract.test.mjs generated` 只读深比较完整对象。不要手改生成 JSON；表源变更归表结构 owner 单独审查。手动导入会改目标数据库模板，须另行确认作用域与备份；本次重新生成不是已导入、旧档迁移或真实宿主验收。
- **镜像**（写）：`persistSelf/persistMemory` 在存聊天档案后顺手镜像——先 `exportTableAsJson` 读最新表，reconcile 出最小差异（删除按原索引从大到小 → 逐行 updateRow → 追加 insertRow），桥接表按「编号」对行，编号为空的手工行不删不碰。
- **受保护收养**（兼容读入，不是表覆盖台账）：恢复聊天后及 `doupoAgent.dbBridgeAdopt()` 手动调用仍可读表。纳戒只接收有效更新时间且不早于本地的表状态（本地无档时也要求有效时间），保留流水与未映射字段；记忆仅在有新增/文本变化且编号未退役时合并，保留本地独有条目、退役编号与流水。空表不清账；过时聊天/飞行期间已变化的结果不会提交。通过护栏的结果仍经运行时写回 `chatMetadata`，不能拿镜像当作完整存档恢复源。
- **外部手改回拉**：`registerTableUpdateCallback` 去抖后仍走上述护栏，再保存聊天台账、刷新面板；桥内活跃写入期间屏蔽自身回调。表格手改不是无条件成功的正式记账入口；本次不移除或改写这条兼容路径。
- **冷聊天兜底**：CRUD 写入需要数据库在当前聊天已有楼层锚点；全被拒时自动改走 `importTableAsJson` 全量导入（锚定最新 AI 楼层），仍失败则记入桥状态、数据留在聊天存档不丢。
- **状态查看**：设置页「纳戒」卡底部的「数据库桥接」行（已连接/未检测到脚本/异常+原因），或 `doupoAgent.dbBridgeStatus()`。

注意：桥接表一旦建立，请勿在数据库脚本里改这 12 张表的表头或 DDL——列名与 `db-tables.js` 里的编解码一一对应（有单测锁定）；改列要走表结构 owner 的代码审查。

## 纳戒 → MVU 变量同步（`host/self-mvu.js`）

把主角档案/境界/金币及功法、装备、行囊、目标等投影到 **MVU（MagVarUpdate）的 `stat_data.斗破纳戒`**（顶层平键，整体覆盖），供状态栏、EJS 模板读取；剧情日仍归世界台账，不在此投影。MVU 帧不是持久状态权威；MVU 主脚本缺失/关闭时同步跳过。默认 `self.mvuChannel='inline'` 的 MVU 变量申报会由扩展仲裁后落入纳戒台账，再投影回帧；不能把申报帧直接当成真账本。

- **写入协议**：MVU 官方的「读帧 → 改帧 → 整帧写回」——`getMvuData({type:'message',message_id:'latest'})` 取该楼变量帧，改 `stat_data.斗破纳戒`，`replaceMvuData` 写回。不要用 `setMvuVariable` 做持久化：源码里它只改内存树、不落盘。stat_data 里别人的键原样保留，缺失的 stat_data 自动建。
- **触发**：`persistSelf`（纳戒决定落账/面板改动）与换聊天恢复后各同步一次；`doupoAgent.selfMvuSync()` / `selfMvuStatus()` 可手动触发与查看。
- **与数据库桥的分工**：纳戒真账本在扩展（chatMetadata），数据库表和 MVU 变量是两个并列的下游镜像；数据库脚本对 MVU 只有读（它把 stat_data 塞进自己的 EJS 上下文），写 MVU 的责任在扩展。
- **不启用 MVU 的"深度分析"**：那是让 MVU 另调一个模型从正文提取变量的可选功能；纳戒数据的更新走扩展决定＋代码投影，零额外模型调用。

## 记忆存储（`memory/`）

主角视角的记忆总账，与各账本所有权互斥（目标约定归纳戒、任务归世界、事件归世界台账、NPC 档案好感归人物簿、原著设定归事实库——记忆一律不碰，决定提示词里写死了这条边界）。**记忆是资产：永久保存、按需召回，脚本从不过期、不封顶、不自动丢弃任何记忆**，删除只由书记官或玩家主动做。分两层，按分量切而不是按寿命切：

- **小记忆**（`small`）：轻量记录的近事杂事，不必重要才记，保持主角"记得这几天发生过什么"；
- **大记忆**（`big`）：值得一直记住的事（恩怨/秘密/伏笔/大事），召回优先级更高；`tag` 是可选标签（恩怨/情报/伏笔/大事记），只便于查看；
- **转大**（`promote`）：小记忆分量够了转成大记忆。
- **召回钥匙**：`related`（1-4 个人名/地名/物名）必填——没有钥匙的记忆永远召不回来，运行时直接拒绝。

1. **决定调用**（`memory/memory-decide.js`）：世界决定结束后的回调会启动影响、纳戒与记忆各自的后台链，但不等待前两条全部完成，不能承诺记忆读取到它们当轮的新账。记忆决定读最近聊天、相关设定与本场召回记忆，输出 `{"note":"…","ops":[…]}`（≤12 条）逐条校验；`memory.decideAuto=false` 停止自动决定，仍可手动调用，正文 `memory` 指令解析作为兼容入口保留。连接与喂料使用独立的 `memory.decide*`；`memory.decidePrompt`/`memory.guide` 留空跟随内置默认。
2. **操作集**：`remember`（小记忆）、`memorize`（大记忆，模型通道自动降为 remember）、`promote`（仅面板手动）、`forgetMemory`（记错删除）；公共字段 title 必写≤14字（列表主页只显示标题）、text≤300、basis 必写≤80、related 必写≤4、quote≤60（当时的一句原话，召回时以「」带回）、note≤200（细节补充）、weight major|minor。同层同文不重记；**账本无上限**，脚本从不自动清理。
3. **召回决定与注入**（`memory/memory-recall.js`）：用户输入之后、生成之前，把**记忆目录（编号|层|标题|钥匙）+ 最近聊天（含最新玩家输入）+ 世界书命中**交给召回模型，挑出本轮要注入的编号（≤12 条、按相关度排），脚本按编号取条目注入独立通道 `doupo_memory`；结果按楼缓存，重 roll 不重复调用。**召回失败/关闭 → 关键词兜底**（`memory-ops.recallHits`）：最近四楼正文整词比对 `related`+`aliases`，排序 = 大记忆 → 关键 → 新的优先（无强度权重），超预算从尾部丢。`findMemoryConflicts` 用 bigram 相似度在同钥匙记忆里找疑似重复/矛盾，面板标 ⚠ 只提醒不拦账。
4. **脚本执行**（`memory/memory-runtime.js`）：越界数值、未知操作、缺 related 只拒绝不炸；同楼重 roll 先撤销上一版指令再落新账；opId 去重防重复喂入。
5. **持久化**：整份记忆以 `chatMetadata.doupo_agent_memory` 为权威；数据库桥接开启时镜像到小记忆/大记忆两张表（引文/别名，标签仅大记忆）。换聊天与外部手改仍保留受保护收养，但记忆按内容与退役编号合并，纳戒按更新时间判断；两者护栏不同，均不代表镜像表优先（见「数据库桥接」）。
6. **面板**：设置页「记忆存储」——总览、**记忆注入卡**（最近一轮实际进入提示词的记忆：来源/条数/字数/时间，点条目看完整记录）、**排序切换（按生成时间 / 按分量 / 按标签分类）**、**按关联过滤**（下场对手戏前按人扫旧账）、大记忆/小记忆两栏清单（转大/提关键/删除、引文与别名展示、⚠ 矛盾标记）、手动登记（层级+标签+关联+别名+引文+备注）、召回开关与预算、决定/召回两套开关、两份提示词改写、指令流水。手动操作与模型决定走同一套校验。悬浮球记忆面板同款：摘要带「本轮注入了 N 条」，头部是**已注入的记忆**列表（点开详情），记录随聊天存档走、生成结束自动标「已清理」。
7. **命名空间**：`doupoAgent.memoryStatus()/memorySnapshot()/memoryApplyPersisted()/memoryDecide()/memoryRecall()/memoryRestoreFromChat()`。

### 记忆召回与数据库表（绿光条目默认关闭）

记忆召回由扩展自己的**召回决定**负责（见上）：注入预算与挑选逻辑都在扩展侧。小/大记忆表保留 **`exportConfig`（导出配置）** 形状，但 `enabled:false` 默认关闭，避免扩展注入与数据库条目重复进入提示词。这不是面板可选召回模式；若另行改为数据库召回，必须由 owner 单独评估注入去重与预算，不能只翻开关。以下仅解释保留的配置：

- **触发词** = `关联,别名` 两列（逗号分隔的列名）；行里这些列的值再按逗号切成一个个触发词，人名/地名出现在最近楼层就整行注入。
- **注入模板**：小记忆 `<记忆近事>$1</记忆近事>`，大记忆 `<记忆存储>$1</记忆存储>`。
- **关联/别名列用逗号连接**（数据库的触发词拆分只认 `,` `，`，不认顿号）；扩展台账内部仍是数组，读取时兼容顿号旧行。
- 配置跟着表格定义走（`db-tables.js`），数据库脚本一行不改；桥同步时同表同表头但导出配置对不上会原位刷新（算 `updated`）。

### 楼层显示美化（`host/display-regex.js`）

数据库召回会把用户楼层原文改写成「以下是用户的本轮输入 + `<本轮用户输入>`正文 + 召回导语 + 时间约束词表」，纯文本裸奔在楼层里。扩展启动时往酒馆正则扩展的全局列表注册四条**仅格式显示**的正则（`markdownOnly=true`、`runOnEdit=false`），只改渲染：存档原文不动、提示词不受影响、编辑楼层看到的仍是原文。

- **输入段空行守护**：输入段内的空行压成单换行——markdown 的 HTML 块遇到空行会截断，卡片会散架。
- **本轮输入卡片**：输入段包成 `.dpz-round` 卡片（简约玄幻：细金线 + 四角符箓 + 淡金底晕，样式在 `host/style.css`；酒馆会给楼层里的 class 加 `custom-` 前缀，两组选择器都写全）。
- **召回导语收纳**：从「以下输入的代码为既定事实记忆…」起整段收走——那是提示词的家什，玩家没必要在楼层里看。
- **旧楼层隐去**：屏幕上只留最近三楼。给每一楼开头钉一个空帷幕标记 `.dpz-floor-veil`（内容原样保留，用户楼与 AI 楼都钉），收不收由 `host/style.css` 按位置动态决定——带标记又不在 `#chat` 最近三块里的整楼 `display:none`。不按渲染时刻算深度：酒馆出新楼**不会重渲染旧楼**，按深度清空会让“留几楼”越漂越远；按位置算，新楼追加、删楼、插入都自动重算，永不漂移。要改保留楼数就改样式里两处 `-n+3` 的 3；想看全史，正则面板关掉这条脚本再重进聊天即可。
- 同名脚本已存在一律不覆盖（正则面板里可见、可改、可关，用户手改的为准）；首次补装后自动 `reloadCurrentChat` 让老楼层立即生效。

### 已退役兼容：合并决定

合并决定不再是可启用的运行模式：`self.decideMerged` 是迁移时清理的旧键，`unifiedActive()` 恒为 `false`；保留的 `doupoAgent.unifiedDecide()` 只返回 `{ status: 'retired' }`，不发模型请求、不提交纳戒或记忆操作。`unified/unified-decide.js` 的纯解析函数留作兼容，不代表入口仍在运行。

- 默认纳戒走正文 MVU 申报；可选独立纳戒决定绑定 `self.decideApiPreset`，记忆决定绑定 `memory.decideApiPreset`；记忆总结沿用记忆连接，两域不再共用合并开关。
- `cited` 已不再有消费方，`recallCount`/`markRecalled` 也不是当前记忆合同；召回由独立召回决定及关键词兜底负责。
- `writeMemoryInjectionForPrompt` 依 `enableMemoryLedger`、`memory.inject`、`memory.recallEnabled`、`memory.recallAuto` 选择禁用/召回/关键词兜底，不因旧合并键委托给数据库。保留兼容 API 不等于恢复旧功能。

## 开放世界（`sandbox/`）

`enableSandboxMode` 打开后（正式口径记录以 `sandbox-mode.js` 为准，中途切换要确认），世界换成**开放的斗破苍穹主世界**——不跟随原著剧情，原著故事不是日程表；方向不单设，世界运转的任务与传闻就是递到玩家手里的方向：

- **不用世界书**：原著设定注入与设定挑选整条停用（`getSettingBudget` 直接返回 null，设定挑选的模型调用也省掉），正文注入通道改写内置**斗气大陆基线**（`sandbox/sandbox-world.js` 的 `SANDBOX_WORLD_PROMPT`，以世界书常驻体系条目为底稿：斗气阶梯/功法四阶/炼药师/异火榜/魔兽魔核/中州格局）。
- **决定喂料换血**：世界决定不再带世界书条目，改带 `SANDBOX_DECIDE_NOTE` + 斗气大陆基线；纳戒/记忆/合并/影响/记录员的决定喂料在开放世界下一并停用世界书条目。远地的事按既有契约走 `rumor` 传闻事件（查证后 `resolveEvent` 了结），不新增系统。
- **总控可见**：总控页「运行口径」卡显示当前口径与正式记录状态；原著设定页的「上次注入」在开放世界下显示的就是斗气大陆基线。
- 玩家目标、目标上限等设置不单设——目标就是世界任务（`world/`），开放世界只是不再替玩家排剧情。

## API设置（接口方案）

设置页「核心能力 → API设置」把每套接口配置存成命名方案（最多 20 个）：名称、协议（自动判断/OpenAI 兼容/Anthropic）、接口地址、API Key、模型（可点「拉取模型」从列表选）、采样参数（温度/最大输出/top_p/两个惩罚项，0 ＝不指定），以及与酒馆「自定义接口 · 附加参数」同语义的三段附加参数——**包括主体参数**（YAML 对象，最后并进请求体，例 `top_k: 20`）、**排除主体参数**（YAML 数组，最后从请求体删顶层字段，例 `- frequency_penalty`）、**包含请求标头**（YAML 对象，合并覆盖请求头、可覆盖鉴权头）。酒馆是服务器端用 js-yaml 解析这三段，扩展在浏览器里直连，所以自带一个覆盖酒馆文档全部示例用法的迷你 YAML 解析器（`host/api-presets.js` 的 `parseYamlBlock`，JSON 直接透传）。方案只保存在扩展设置里（密钥也是，与 `llm.apiKey` 同口径，不进聊天消息）。

## 模型设置（只选方案）

「模型设置」页每张卡只回答一个问题：这个功能用哪套方案（schemaVersion 11 起）。15 个绑定键——全局连接/原著设定/行动结算分类/行动结算最终判定/世界决定/记录员/**档案抄录**/**经历精简**/冷藏推进员/**纳戒决定**/**记忆决定**（合并决定已退役，这是两条独立调用：各绑各的方案、各喂各的楼层）/**记忆召回**/**记忆总结**/世界影响记录员+场记，统一存 `*.apiPreset`/`*.decideApiPreset`。**不绑方案＝跟随酒馆主连接**；绑了方案，该功能的每次调用整套走方案（接口、参数、附加参数按酒馆同序套用：先并主体、再排除、标头最后覆盖）。旧的每卡手填字段（模式选择/地址/密钥/模型/采样参数/每卡拉取按钮）已全部删除；升级时 host-storage 的 `migrateLegacyApiPresets` 把各卡 `mode=custom` 且填了地址的旧配置一次性搬成方案并自动绑定（字段完全相同的卡去重共用一个方案，搬完该组 `mode` 落回 tavern，重跑无事可做，删掉的迁移方案不会复生）；v11 拆分把拆分前“纳戒与记忆共用”的绑定与喂料复制给纳戒做起点（版本门只跑一次，之后两侧各改各的）。场记不绑方案就跟着记录员；档案抄录/经历精简的任务级温度与上限补丁仍叠在各自方案之上；删除方案时指向它的功能自动回到跟随酒馆主连接；`self.decideMerged` 死开关随合并决定退役一并清理。跟随酒馆路径（`generateQuietPrompt`）没有附加参数落点，方案仅作用于自定义接口直连。跟随酒馆时采样参数不再单独指定（沿用酒馆/全局自己的设置）；要参数就在「API设置」页建方案。

## 三个宿主适配器

- **模型**（`host/llm-client.js`）：连接方式二选一（`llm.mode`）——跟随酒馆当前 API（`generateQuietPrompt`）或自定义接口；自定义接口支持 OpenAI 兼容（`/chat/completions`）与 Anthropic 兼容（`/v1/messages`，`x-api-key` 鉴权、system 独立字段、content 文本块拼接）。旧版只有 `useSillyTavernConnection` 开关的配置会按老开关自动迁移到 `mode`。没配好时这一轮直接返回“模型连接未配置”，不会静默跳过。
- **消息**（`host/message-adapter.js`）：用 `createChatMessages` 把正文写进当前对话，再回读聊天列表确认最后一条就是它；确认不到就不提交状态。
- **存档**（`host/state-persistence.js`）：状态、历史与版本号存在 `chatMetadata['doupo_agent_state_v1']`，按会话与分支隔离，切换聊天会重新载入。

## 数据合同

`doupoAgent.contracts` 登记对象、字段、类型、唯一写入者和允许读取者，开局自带 `player` 与 `world` 两张表。质量门只接受已登记字段的写入，写入者必须与该字段登记的 writer 一致，所以模型编出来的字段（比如 `player.luck`）会被直接拒绝，而不是悄悄写进状态。

## 主要接口

- `doupoAgent.runTurn({ sessionId, branchId, input, triggerMessageId })`：跑一轮，返回 `completed / needs_clarification / rejected / failed / save_uncertain / disabled / unavailable`。
- `doupoAgent.inspectTurnState({ sessionId, branchId })`：读当前状态与版本。
- `doupoAgent.pipeline` / `doupoAgent.stages` / `doupoAgent.orchestrator`：直接使用管线、阶段或编排器。
- `doupoAgent.router` / `doupoAgent.quality` / `doupoAgent.narrative` / `doupoAgent.commits`：路由、质量门、叙述门与提交恢复。
- `doupoAgent.facts` / `doupoAgent.actions` / `doupoAgent.world` / `doupoAgent.npcs` / `doupoAgent.sandbox`：资料、行动、世界、NPC 与沙盒能力。
- `doupoAgent.npcLedger` / `doupoAgent.npcLedgerRecord()` / `doupoAgent.npcLedgerApply(patch)` / `doupoAgent.npcLedgerExtract({ names, overwrite })` / `doupoAgent.npcLedgerSetPlayerContext(fn)` / `doupoAgent.npcLedgerStatus()`：人物簿的查、记、手填、按世界书重抽、玩家处境接线与控制台状态。
- `doupoAgent.npcColdRuntime` / `doupoAgent.npcColdSelect(name)` / `doupoAgent.npcColdDeselect(name)` / `doupoAgent.npcColdPreview()` / `doupoAgent.npcColdConfirm(id)` / `doupoAgent.npcColdDiscard(id)` / `doupoAgent.npcColdStatus()`：冷藏人物选择、扫描草稿、确认写回、放弃草稿和状态查看。
- `doupoAgent.selfRuntime` / `doupoAgent.selfApply(ops, { floor, day })` / `doupoAgent.selfDecide()` / `doupoAgent.selfApplyFromLatestReply()` / `doupoAgent.selfStatus()` / `doupoAgent.selfSnapshot()` / `doupoAgent.selfJournal()`：纳戒的运行时、手动落账、手动决定、正文指令块解析、状态与流水。
