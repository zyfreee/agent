# 斗破同人 Agent · 酒馆扩展

一个跑在 SillyTavern 里的文字游戏总控。默认由酒馆生成正文，扩展做生成前注入、生成后各域记账，并把台账保存到当前聊天；扩展自行编写和投递正文的手动回合管线是默认关闭的旧链。能力通过 `doupoAgent` 命名空间提供。

## 可选旧链：手动结算一轮（默认关闭）

1. **解析**：把玩家消息交给模型，得到结构化意图（类型、任务、明确行动、效果、天数）。
2. **授权**：分类器判断这轮是闲聊、查询、明确行动还是时间推进；行动必须由玩家自己说清楚才放行。
3. **计划**：路由器只把任务分给白名单模块（资料查询 / 行动结算 / 世界推进 / 开放世界推进），越权请求直接拒绝。
4. **六阶段管线**：`classify → plan → gather → adjudicate → compose → validate`，每阶段有超时与输出上限，总预算 90 秒。
5. **两道门**：质量门核对作用域、字段登记、唯一写入者与玩家授权；叙述门核对正文里的每条事实是否有依据。
6. **两段式提交**：先把正文发进对话并确认消息可见，再提交状态；提交成功后状态版本 +1，并写入 `chatMetadata`，刷新页面后仍在。

以上描述的旧回合管线已整体退役：`ui.legacyTurn` 开关随「旧版手动脉冲」设置卡移除，「结算这一轮」手动入口一并下线，这套管线不再可达。它不是下面默认的酒馆正文生成与后台台账链。

## 原著设定怎么进提示词（默认路径）

正文默认交回酒馆自己生成，扩展只负责在生成前把“这一轮真正需要的原著条目”塞进提示词：

1. **建索引**（启动时、切聊天时自动跑）：`setting.worldbook` 填世界书名，扩展用 `loadWorldInfo` 只读它，按 `comment` 里的「题名（类别-名字）」拆出类别、名字、别名；卷号来自 `世界书/tools/build-volume-index.mjs` 生成的 `narrative/volume-index.generated.js`。
2. **发目录**：当前卷的条目按 `uid|类别|标题|摘要` 排成目录（故事线只给标题，前情只给标题、不铺后续卷）。目录先按与本轮输入/最近对话的词面相关度重排（`facts-index.js` 的 `rankCatalogFor`：key 子串 > 字符命中率 > 摘要二字窗），命中行置顶、零分行的摘要降级成 `—`；行集合与原目录完全一致，只排序与瘦身，选条仍由模型点名，空输入回落 uid 序。
3. **模型点名**：一次 `generateQuietPrompt` 静默生成，只回 JSON `{"need":[{"uid":11,"why":"..."}],"no_match":false}`；`jsonSchema` 一并传给酒馆。
4. **脚本取货**：uid 必须在目录里，越界丢弃，最多 6 条；按 `injectionBudget` 预算裁到整条或摘要。
4½. **卷外兜底**：目录里没有、但模型判断必须用到的，它把名字写进 `"lookup"`；脚本全库搜（标题、key，再垫一层字符级模糊：≥3 字且命中率 ≥0.6 的变体名也捞），把候选带卷号列出来再问它一次，只接受候选里的 uid。没给名字或全库搜不到，就不发这次额外调用。
5. **注入**：`setExtensionPrompt(key, text, IN_CHAT, depth=0, scan=false, SYSTEM)`，生成结束或中断时清空；文字不进聊天记录、不写世界书。
6. **对账**：正文里出现“没注入过的条目名”记一条 `unapproved_setting_use` 审计，不拦生成。

世界书侧的分工是硬边界：**启用中的条目仍归酒馆原生注入**（28 条体系 + 1 条原著分卷汇总），插件导入时会把它们跳过，只接管关闭的 1132 条明细——同一段设定永远只走一条路。`node 世界书/tools/worldbook-disable.mjs --write` 负责把明细全部关掉，只留启用层；`node 世界书/tools/add-volume-index-entry.mjs --write` 会按 `原著分卷/卷NN_标题.txt` 重建那条常驻的《原著分卷汇总》（constant、order 100）。两个脚本都默认干跑，写前留带时间戳的备份。

插件只读不写：注入走 `setExtensionPrompt`，从不调用 `saveWorldInfo`，世界书的启用状态、文件和酒馆其它功能都不受影响。

设置页「原著设定」里的对应关系：检索库状态显示已索引条数、七分类分布、缺卷号条数和当前卷目录行数；「世界书名称」可手填，点“扫描可选世界书”会尝试列出酒馆里的世界书名字（酒馆版本不支持时回退为手填）；改动名称后会自动重同步索引，也可点“从世界书导入”手动重建。下面的「注入通道」控制是否注入、插入深度和最大字数。

手动“结算这一轮”的旧链路已退役（`ui.legacyTurn` 开关已随「旧版手动脉冲」卡移除），正文始终由酒馆主生成，两条链路抢正文的问题不复存在。

选条提示词（模型看到的 system 指令）写在设置 `prompt.select`：留空用内置默认，`MAX_PICKS` 会替换成当前上限，改完下一轮生效，不用重启。

## 正文核验（narrative/verify-claims.js）

生成结束后的一次旁路小调用（`runFactCheck`）：把最新 AI 楼层的正文拆成可验证的原子断言，对照本轮注入的原著条目与三本台账现状行（世界/纳戒/人物）逐条裁决，**只记审计、不拦正文**。裁决取三标签口径（VeriScore，EMNLP 2024）：`supported 有据 / contradicted 矛盾 / unverified 无据`。它核「事实有没有依据」（防编造），与人物一致性体检（`npc/npc-consistency.js` 核「写法合不合人设」）分工互不重叠；设计与裁决规则详见 `narrative/VERIFY-DESIGN.md`。

1. **触发与顺序**：排在世界/纳戒/人物记账链**之后**（`scheduleFactCheckAfter` 等记账 Promise 落地）——台账没记完就开核，会把“本轮刚发生的变化”误判成矛盾。楼层防重与世界决定同款；失败生成不算数。
2. **快筛**（`verify.gate`，默认开）：正文命中条目名/在册人物名/境界段位/数量词之一才发起调用；闲聊楼层零调用、零审计。
3. **名字比对（默认关）**：`setting-supply.audit` 的确定性检查——正文出现未注入条目名记 `unapproved_setting_use` 审计，零模型调用。**实跑发现 lore 密集的卡上一楼能记 40+ 条**（原生世界书注入的设定被正文引用是常态），故 `verify.nameAudit` 默认关，要漂移报告再打开。
4. **裁决规矩**（内置提示词 `VERIFY_PROMPT`，`verify.prompt` 可改写）：`contradicted` 必须有明确相反的证据行（basis 写 `entry:<uid>` / `ledger:world|self|npc` / `rumor` / `none`）；传闻只许判 `unverified`；断言 text 必须是规范化表述、逐字复制正文原句的拒收（审计合同：不存正文）；坏 JSON 带原因重试一次（重试**去掉 jsonSchema** 裸跑），再坏放弃本轮。
4½. **调用通道走 `generateRaw`（独立提示词）**：实跑复现，卡片的工具协议（如「小猫之神」卡的 `soliumbra_reply`）会把 `generateQuietPrompt` 劫持成 tool_calls，调用方只拿回工具返回值 `{}`，真正的 JSON 被工具执行器吃掉；`generateRaw` 不拼角色卡/主聊天预设，证据在 user 里自含，天然绕开。结构化输出 schema 也只写酒馆执行器认的关键字（`additionalProperties`/`description` 会把约束生成压成 `{}`，照 `DECIDE_JSON_SCHEMA` 的口径写）。
5. **落账**：条目与豁免集存 `chatMetadata.doupo_agent_verify`（FIFO 200 条；误报标记带 revision 乐观锁，标记后同断言键进豁免集不再重记）；`lastRun`（floor/ts/status/claims/nameIssues/reason）每次跑完必落——区分「跑了没结果」与「没跑」，skipped 不落；每轮调用记 `turn_fact_check` 审计事件（运行日志可查）；悬浮球总控的「原著设定」行尾挂「核验」渠道标记；`doupoAgent.factCheck({source})` / `doupoAgent.factStatus()` 供控制台调用。设置卡在「原著资料」页，连接方案在「模型设置」页。

当前卷有两种来源：面板“当前剧情卷”填了就是手动锁定；留空时走自动判定——模型在选条 JSON 里顺带给的 `volume`，加上“正文里出现故事线标题原文”这一条兜底，取较大值，且一轮最多前进一卷。判定结果写回 `facts.currentVolume`，运行状态卡会显示当前卷、来源和自动值。

## 世界事件系统（world/）

**LLM 决定脚本执行**是主路径：生成结束后，扩展发起一次独立的模型决定调用——模型读**最近聊天 + 相关世界书条目 + 世界台账**，输出严格 JSON（`{"note":"…","ops":[…]}`，附 jsonSchema 约束），脚本逐条校验执行，结果（模型说明 + 每条操作 ✓生效/✗被拒）呈现在设置页「模型决定」卡里。

1. **决定调用**（`world/world-decide.js`）：默认提示词 `WORLD_DECIDE_PROMPT` 写死事件取材与输出契约；设置页「模型决定」卡的**决定提示词**框打开就显示当前生效的完整正文（留空时自动铺入内置默认，所见即模型所收），直接改、清空则恢复跟随默认，`world.decidePrompt` 存改写版。世界书侧输入按本轮聊天去 facts 索引匹配条目（`uid|类别|标题|摘要`，上限可设），不铺全文。模型与温度可在设置里单独覆盖（独立接口模式生效；酒馆连接沿用当前模型）。`world.decideAuto` 关掉后退回"只认正文指令块"的降级模式（指南随现状注入，回复末尾 ```world 代码块照旧解析）。
2. **脚本执行**（`world/world-runtime.js`）：越界数值、未知操作、超长文本只拒绝不炸；同楼重 roll 先撤销上一版指令（含被它到期了结的事件）再落新账。
3. **操作集**：`advance`（天/分钟）、`setClock`、`addEvent`（scope near|world、title 短标题必写≤16字、basis 依据必写、weight minor|major|rumor、days 有效天数≤90、`participants` 事件点名≤3人、`cause` 起因事件编号）、`resolveEvent`（可带 `outcome` ≤80字了结结论）、`updateEvent`（推进已登记事件的阶段：改 text/weight/title/days，大事酝酿→爆发、传闻升级实锤都走它）、`pinEvent`、`setInfo`（weather/location/era/reputation 名声/wanted 通缉度）、`addTask`（title 必写/detail/basis/days 时限）、`completeTask`、`deleteTask`、`updateTask`、`setFaction`（势力名/stance 敌对|警惕|中立|友好|同盟/动向/依据，按名字 upsert）、`deleteFaction`、`setPerson`（人物名/态度/依据）、`deletePerson`、`setTension`（世界氛围 calm 平静|rising 升温|storm 风波）。事件可带 `location`（事发地点）；决定规则要求事件符合所在地特征（魔兽山脉是兽袭与药草，帝都是权贵与阴谋）。任务规则：玩家承诺或接下的事、人物托付、剧情给出的明确目标才立任务；任务栏会注入给正文模型，完成后 completeTask、作废 deleteTask、进展 updateTask。势力与人物只在剧情真的接触或关系变化时更新，不照世界书预登记。季节为推导值：一年 360 天四季轮转，注入的时钟行与面板都显示季节，环境描写要跟季节对上；固定大会/仪式用 addEvent 带未来 day 登记成预定事件（注入标「预定：第X天」）；advance 一次跨 7 天以上（闭关、赶路）时，决定模型必须补 1-3 条跳跃期间的动向事件，没补的话运行时记一条「空窗」警告并在决定结果卡显示，出关时世界不是原地等你。
4. **事件取材规则**（提示词里写死，可改写）：事件从聊天记录里有依据地长出来，题材不拘（市井琐事、势力动作、传闻），basis 必须写清从哪来；没有依据不记，不把世界书里的原著桥段照搬成事件。**rumor=传闻**：未证实消息，正文不得当事实写，查证后 resolveEvent 带 outcome 写结论，真相或戳穿另记一条并用 cause 关联原事件（了结链在流水与面板可见）。**事件点名**：addEvent 能点名就带 participants（台账「相关人物」「势力动向」里已有的名字，≤3个），后台靠它知道事件牵连到谁——冷藏推进与传闻传播的匹配优先认点名。**机遇与危机**（拍卖会、药草成熟、仇家寻上门、势力清洗）属于世界主动投放的 major 事件：偶尔来一件、必须有依据。**名声/通缉度**只在剧情真有对应行为时更新，注入的现状行会显示。
5. **到期清扫**：时限事件推进过线自动了结并留流水；注入列表显示"剩 N 天"。
6. **持久化**：台账整体存 `chatMetadata.doupo_agent_world`，随聊天保存；切聊天自动恢复。
7. **面板**：全部集中在设置页「世界运转」——世界时间与现状卡（时钟、手动推天/设钟，时期/所在地/天气/名声/通缉度五个信息字段手动设定）、双栏事件（剩余天数、传闻标记、了结/置顶）、**任务卡（进行中/已逾期/已完成全部列出，详情完整展示，每条可手动完成/删除，也可自己接任务）**、手动登记事件（范围/分量含传闻/依据/有效期）、模型决定卡、指令指南与决定提示词改写、指令流水。手动操作与模型决定走同一套校验。

上限保护：单批最多 12 条操作（解析截断 12、运行时执行上限 12，已对齐）、事件单栏最多 60 条（先清已了结、再清未置顶最老的，置顶永不清理）、事件文本 300 字、信息字段 80 字、单次推进最多 365 天。重复登记三道防线（都只看同栏未了结的事件）：同文 `duplicate_text`、同标题 `duplicate_title`、几天内标题相似度过线的近似重复 `duplicate_similar`（与世界影响库共用 `core/text-similarity.js` 的双字重合度算法）。**氛围管投放节奏**：事件注入条数按氛围取档（calm 6/4、rising 8/6、storm 8/8），传闻传播上限 calm 2 / rising 3 / storm 4，不再只靠提示词里的一句"跟氛围匹配"。


## 剧情账本（`plot/`）

**滚动计划 + 线索账**是叙事层的长篇一致性台账：世界台账记"世界发生了什么"，这里记"故事要往哪走、埋了哪些还没回收的线"。生成结束后一次独立的剧情决定调用——模型读**最近聊天 + 世界时钟 + 账本现状**，输出严格 JSON（`{"note":"…","ops":[…]}`，附 jsonSchema 约束），脚本逐条校验执行。排在世界决定之后跑（世界账落定才有可信的时钟），结果呈现在设置页「世界运转」的「剧情账本」卡。

1. **决定调用**（`plot/plot-decide.js`）：默认提示词 `PLOT_DECIDE_PROMPT` 写死计划与线索规则；`plot.decidePrompt` 留空跟随内置默认，改写时保持"只输出 JSON"与操作字段名不变。解析失败会带错误信息自动重试一次（instructor 式），再失败才整轮作废——坏输出不再一票否决。连接在「模型设置」页「剧情账本 · 决定模型」卡（方案绑定 + 喂楼数，与世界决定各自独立）。
2. **操作集**：`setPlan`（goal 本幕目标≤60、next 下一步≤120，只写要改的字段）、`addThread`（title 必写≤16、basis 必写、kind=foreshadow 伏笔|suspense 悬念|conflict 恩怨、detail≤200、dueDays≤90 预期回收窗口）、`updateThread`（推进详情/延期）、`resolveThread`（回收，可带 outcome≤80）、`dropThread`（作废）；一次最多 8 条。
3. **运行时**（`plot/plot-runtime.js`）：越界数值、未知操作、超长文本只拒绝不炸；运行时自己不拥有时钟，`apply({today})` 由调用方喂世界台账的当前天数，悬置天数与超期判定都按它算；同楼重 roll 先撤销上一版指令再落新账。重复防线：开放中的同标题 `duplicate_title`、两天窗口内标题相似度过线 `duplicate_similar`（与世界台账共用 `core/text-similarity.js`）。开放线索最多 12 条，超了拒绝（`threads_full`），回收一条空位让出来；已回收的同名线索允许重埋，编号继续前进。
4. **注入**（`plot/plot-ops.js`）：生成前把「剧情前瞻」写进独立通道 `doupo_plot`，与世界、影响、人物簿、纳戒、记忆、原著设定各路互不清空——计划两行永远保留，线索按悬置越久越靠前，超期的置顶标「已超期未回收」，每行带悬置天数；超预算先丢线索保计划，线索丢光时栏头一起退场。账完全空时不注入。
5. **持久化**：整份账本存 `chatMetadata.doupo_agent_plot`，随聊天保存；切聊天自动恢复。调度链捕获本轮 continuation：等账落定时已经换了聊天就随旧聊天作废，不在新聊天起飞。
6. **面板**：设置页「世界运转」的「剧情账本」卡——启用/注入开关、注入预算、决定开关与自动、手动「让模型决定一次」、账面视图（滚动计划 + 开放线索带悬置标记）与剧情指令流水、决定提示词改写。手动逐条编辑线索暂未开放（模型决定与自动维护为主）。

分工边界（提示词里写死）：世界事件/任务归世界运转，人物态度归人物簿，主角状态归纳戒；这里只管叙事层——本幕目标、下一步走向、未回收的伏笔/悬念/恩怨，不要把任务当线索重复登记。简略版（lite）暂不接剧情决定。

## 悬浮球（`host/orb-hud.js`）

屏幕右侧挂一颗小球；点一下，球竖直拉伸成一根胶囊长条（顶上和底部都是半圆），条上从上到下排十二个图标：总控 ⌂、世界运转 ◌、纳戒 ◉、记忆存储 ✧、人物簿 ☰、冷藏推进 ❄、世界影响 ⌁、原著资料 ▤、行动结算 ⚖、数据镜像 ⇄、运行日志 ✎、开放世界 ◈（胶囊末尾另有一颗「Agent 系统」⚙ 入口齿轮，直开设置面板，不算信息窗）。点图标弹出对应功能的**只读信息窗**——世界运转有时钟/季节/时期/所在地/天气/名声/通缉度/世界氛围、双栏事件、势力动向（敌对排前）、相关人物与任务；纳戒有身份/境界/金币计数与称号、功法、斗技、行囊、配方、炼制中、目标七份清单；记忆存储有大记忆/小记忆两栏（关键排前、带引文/关联/标签）；数据镜像显示数据库桥接（12 张桥接表）与 MVU `stat_data.斗破纳戒` 的同步现状；总控窗的模块行尾直接挂该模块名下调用渠道的实时标记（已开启后一眼看清哪路没调）——在途转圈、完成打勾（带时间，悬停看详情）、失败打叉（带原因）、没调过写「无」，记忆模块并排挂召回+决定两个标记，剧情账本挂「剧情决定」，已关闭的模块不挂标记，数据来自 LLM 客户端的在途跟踪与调用体检，调用起飞/落地事件驱动就地刷新；总控窗的渠道标记短名常显（状态列/渠道列一列列对齐），**每一路可重跑的调用在自己标记上挂一枚重roll 圆圈箭头**——一行两路请求就有两枚箭头，箭头长在谁身上，重跑的就是谁那一路（走 `source:'manual'` 绕过防重缓存，同楼重跑由各账本撤销上一版再落账）：选条/召回/挑选重roll＝立刻按当前聊天重挑一遍（下一次生成前拦截器照常重跑）、决定/记录/核验各路照旧（行动结算＝预览判定不注入，注入仍只发生在生成前拦截器）；该路调用在途时箭头禁用自转（忙碌态由标记的 running 态数据驱动，不怕总控窗高频重画）；简略版总控三行同款箭头（素材总挑选＝重roll 挑选、行动结算＝预览判定、总结算＝重roll 结算，分路全关的行不给）；总控窗顶部还有一行**「上次失败」**：最近一次失败的调用与短摘要置顶显示（warn 色，没有失败就不加行），**整行可点——弹一张错误详情小卡**（状态码/端点/错误文本/响应体分组展示，手机没有悬停、点击是唯一入口），悬停提示也带完整原因；失败的 ✗ 渠道标记同样可点弹卡；运行日志把审计流水倒序列出（事件与结果都翻成中文）；人物簿只有档案计数与人物一览（好感刻度照搬）；其余各窗同理。窗内控制条只放各路「重roll 决定」按钮（重跑该路模型调用）和纳戒窗独有的「初始化」入口——点开弹出纳戒初始化弹窗，字段与落账路径都走设置页「初始化主角档案（MVU）」同款（applySelfOps → persistSelf → MVU/数据库镜像），留空项不动；其余改状态仍走设置面板。

交互：再点同一个图标关信息窗（长条保留）；点球或按 Esc 或点页面其他地方收起整条；换图标直接换窗。**人物簿一览的每一行可以点开**：在信息窗外侧弹出一张只读小档案卡（抬头好感、角标在场/重要/位置/身份、按组只列有内容的字段、最近三条经历与流水），点同一个人收起，Esc 先收卡再收长条，回合事件到达时小卡跟着重画。信息窗在回合状态事件到达时自动刷新。**进阶版的视觉区分（轻量徽章式）**：总控窗标题旁一枚「进阶」徽章，信息窗描边换强调色并加外光环、球体光晕略强——主题配色不动，完整版/简略版无这些样式。图标多到超出屏幕时胶囊会被视口高度截住、可直接滚动（滚动条隐藏）；设置页「总控」的**显示悬浮球**开关（`showOrb`，默认开）控制显隐；配色跟随界面颜色三主题。

分工：`host/orb-hud.js` 是纯逻辑（图标清单 `ORB_ITEMS`、展开/收起状态机 `createOrbState`、十二个信息窗的数据投影 `buildOrbPanels`），全部输入可为 undefined、不碰 DOM，只从纯逻辑模块借几张现成标签（季节 `seasonOf`、势力立场/世界氛围、记忆标签）；挂载、动画与事件接线在 `index.js`（`mountOrbHud`/`syncOrbHud`/`collectOrbData`），样式在 `host/style.css` 的「悬浮球」段。哪路运行时没就绪，对应的窗就显示「暂无」，不会报错。`dev/orb-smoke.html` 是离线冒烟页：静态服务器打开后自动激活扩展并灌演示数据。

备料闸门：`generate_interceptor` 在每次正文调用前跑完备料链（场记挑选 → 记忆召回 → 行动结算），任何一路失败就调用酒馆的 abort **直接终止本次正文**——页面上不弹报错，失败那路在总控行尾打叉；重发或重roll重试时，已成功的备料走轮次缓存复用（行动结算按「用户楼层及之前的逐层内容」做轮次键，重roll换 swipe 不重调），只重调失败的那几路，全部成功才放行正文。失败结果一律不入缓存。

难度+骰子裁定（`settle/settle-difficulty.js`）：模型在 v2 契约里给每个行动报风险档位（受控/常规/冒险/绝望）与带依据的修正（单条 ±3、总计 ±4，越界收敛并记录），脚本掷 d20+修正对难度阈裁定成败——**只降不升**（success 可被降为 partial/failure，failure 绝不升成 success；insufficient/not_executed 不归骰子管），战斗里证据点名的对手境界每高一个大境界强制抬一档最低难度。没报 `difficulty` 的行动＝旧契约输出，完全不掷骰（自定义提示词与老模型零影响）。降级为失败时只保留真实损耗（负向数值/消耗物品）、成功叙事整段作废（原稿留 `claimedOutcome` 供审计，不进注入）；降级为部分成功时由 `settle/settle-consequences.js` 补一条类型×等级的结构化保底代价（【结仇·中】这类前缀，正文必须写出来），模型自己给的结构化代价同样归一化成这种前缀字符串。波折轮（出现降级）再掷一次变数 Oracle（`settle/settle-oracle.js`，默认 25%）：命中就往注入尾部加一条【变数】提示（world 事件词表的 minor/rumor 档，只建议不落账）。结算回答坏 JSON/契约缺失时带诊断重试一次（`buildSettleRetryUser`，预算装不下就放弃），面板行动行会显示「骰 X±修正 对难度 Y（档位）→ 结果」与变数条目。

## 人物簿（`npc/npc-ledger.js`）

正文落地后，人物记录员做一次独立小调用：读最近两楼正文 + 人物簿索引 + 命中的世界书条目，只回一张补丁清单（`{"人物":[{"姓名":"萧炎","好感":3,"理由":"挡了一掌"}]}`），合并交给脚本——好感只记增减，**单次最多 ±10**（模型写 +95 也只记 +10，跨轮累加、±100 封顶），流水只追加、改一次版本号加一、认不出的字段原地忽略、坏 JSON 直说不动档案。下一次生成前按“在场/不在场 × 重要/不重要”四象限挑人写进正文提示词：在场且重要给全字段，其余给一行，又不在场又不重要就不注入；超预算从最不重要的人开始降级成一行，不硬截断。档案跟着聊天存 `chatMetadata['doupo_agent_npc']`，设置页「人物簿」可开关、调节奏、看档案、手动记账；名单里点「改在场 / 改不在场」「标重要 / 降普通」可直接纠正四象限，下一轮照新档位注入。记录员这一路小调用的连接（跟随酒馆 / 自定义接口地址、密钥、协议）和生成参数（模型、温度、输出上限、top_p、两个惩罚项）全在「记录员参数」里填，填 0 或留空即沿用全局。

**按世界书重抽**：正文只写了半截的人，可以点「按世界书重抽：只填空着的字段」——脚本按姓名/别名/称号去原著设定库逐条找，只把还空着的字段补上，正文记下的身份、好感、流水一律不动；“设定库里没找到”会点名报出来。单个人行里的「重抽」是覆盖式重写：身份/外貌/身体/性格/资产按世界书重来，好感、流水、态度、处境、秘密不动（弹窗确认后执行）。

**玩家处境接线口**：记录员要知道“玩家此刻在哪、什么境界”才分得清“萧炎赶来”是赶去哪。这项不自己猜，等外部接：`doupoAgent.npcLedgerSetPlayerContext(() => ({ location: '萧家后院', realm: '斗者三星' }))`，没接就不注入这一行。

**冷藏推进台**：在人物名单左侧勾选需要“留在后台生活”的人，时间只看世界台账当前是第几天。点“扫描需要推进的人物”后，脚本按**三档证据**挑被新事件牵连的冷藏人物——①事件点名（`addEvent` 的 `participants`，最可靠）→ ②正文/依据子串（单字名不参与；短名命中若整个落在别人更长的名字里不算，如「萧炎鼎」不再牵连「萧炎」）→ ③关系一跳（事件点名或正文提到关系人也算）；原因里写明是哪一档。多人扫描走**有界并行**（3 路并发，每人各自带失败重试），结果按候选顺序回填。模型收到原档案、实际日期差、按重要度挑满 12 条的相关事件（major>rumor>minor、同档新的在前；注入材料分块预算，装不下的整条丢并计数，不再从中间截断）、**上次推进留痕**（确认过的记一句摘要、放弃的草稿标明“已放弃”，供下次衔接不复读）和最近正文参考。草稿停在面板里，逐份点“确认写回人物簿”才调用人物簿的唯一写入口；模型写了名单外的人会被**丢弃并计数**（不再并到目标头上）；点“放弃”不改档案但留痕。第一次勾选只建立当天基线，不会把过去的事件硬补给人物；同一天没有新牵连事件不会调用模型；确认后可点**「撤销上次确认」**（只保留最近一次）：人物簿按确认前的整档快照原样退回、游标退回 previousDay、草稿回到待确认。冷藏台不会推进世界钟、不会替其他人写档、不会自动运行。冷藏状态存 `chatMetadata['doupo_agent_npc_cold']`，与人物档案分开。

冷藏推进员可在人物簿页单独设置连接、模型、温度、输出上限、top_p、两个惩罚项和提示词；默认提示词要求“只按明写依据、好感单次最多 ±10、只出 JSON 草稿、留痕只用来衔接不要复读”。这套参数在「人物簿」页与「模型与提示词」集中页各有一份、走同一个 `data-setting` 通道；选“跟随酒馆”时接口地址、密钥与模型名会置灰，免得以为填了会生效。提示词改写版（`world.decidePrompt` / `npc.coldPrompt`）不会自动跟随默认更新——本轮新增的点名/结论/事件推进/留痕规则只在留空跟随默认时生效，改写过的要清空重铺或手动补。

**记录员与冷藏补丁的失败重试**：补丁输出解析失败（坏 JSON、缺“人物”数组）不再直接作废——坏输出和拒绝原因会退回模型重问一次（instructor 式 validate-retry，`npc/npc-recorder.js` 的 `buildRecordRetryUser`），仍失败才放弃这一轮。人物记录、冷藏推进、传闻传播三路同款。

**大变动依据审计**：记录员提示词要求好感单次超过 ±5、或写「经历」时必须带一句「依据」（≤80 字）；缺依据的照常落账（“模型怎么写就怎么记”的取舍不变），但记一条 `npc_unbacked_change` 审计流水，状态行会提示“无依据大变动 N 处”。带依据的存进好感流水的 `basis` 字段。

**短期情绪层（快变量）**：好感是慢变量（±10 步长），情绪是快变量——补丁里的「情绪」键收 `{label, reason}` 快照（最多 4 条），三天（世界天数 + 3）到期自动消散（`decayMoods`，注入前和每次落账时都会清）。注入时全档拼「此刻：恼怒（被当众驳了面子）」、简档拼「此刻恼怒」；情绪里的「理由」不许污染好感理由（归一化排除）。

**四象限内部分值排序**：同档内不再按插入序——动态分值 = 最近出场（主，0-30）+ 近期好感波动（最近 4 笔 |Δ| 求和，封顶 20）+ 剧情钩子（经历数/正在做/秘密，封顶 14）。分高者注入在前，预算紧张时从队尾开始降级。

**全局人物关系图（`npc/npc-relations.js`）**：档案「对他人」三元组的有向边汇总层，随聊天存 `chatMetadata.doupo_agent_npc_relations`。档案里改「对他人」就自动收边（立场从「结仇/师徒/盟友」等自由文本折成八档：血亲/师徒/同门/同盟/友好/中立/警惕/敌对，折不出的落中立）；支持 `npcRelationsUpsert/Asymmetries/hopLines` 手动 API。三件事：①对称体检——单边强绑定（A 认同盟 B 没记）与立场互相打架在「人物关系网」卡里提醒；②二跳注入——生成前把在场人物的一跳/二跳关系链拼成【人物关系网】行带进提示词（超预算整段放弃，人物档案优先）；③关系扩散——冷藏扫描与传闻触达沿边走一跳。删除人物时边跟着清。**可视化**：人物簿页「人物关系网」卡渲染纯 SVG 图谱——玩家居中，NPC 圆周排布（金边=在场、双环=重要、头顶黄点=有情绪、虚线=未建档），边按立场着色带关系标签，节点可拖拽重排、点节点开档案弹窗；明细与对称提醒收进折叠条。**总控页「Agent 能力地图」**：12 个模块一枚一卡（悬浮球同款图标），绿点=本局启用、灰点=停用，悬停看说明。

**冷藏扫描的关系扩散**：`npc-cold-runtime.candidates` 除了本人姓名/别名命中，还接受 `relationsByPerson`（入口把关系图折成“姓名 → 一跳关系人”映射再传入）：事件正文提到师徒/亲属等关系人也算牵连，原因标「经关系牵连：某人」。

**NPC 互写（`crossWrite`）**：冷藏推进等自行活动补丁（带 `logSrc`）的流水里提到其他已建档人物时，往对方流水里也记一条带来源的行（`药老：在山洞里为萧炎护法`），每份补丁最多牵连 3 人、逐人去重；普通正文记账不开互写——记录员本来会给人各写各的补丁。互写结果在 `result.crossWritten`。

**经历精简自动触发（reflection）**：记录员写过「经历」且该人物经历条数 ≥ 40（真上限 120）时，自动出精简草稿（审计 `npc_exp_auto_condense`）；草稿停在人物簿页「确认写回/放弃」——自动的只是出草稿，写回永远要人点头。手动精简照旧。

**传闻触达（`npc/npc-gossip.js`）**：world 台账未了结的 rumor 事件沿关系图跳一跳——不在场、且与传闻出场人物有一跳边的人会“听到”；一次独立小调用按各人性格（traits/雷区/现状态度）出微调补丁，好感限 ±3（比 ±10 更紧）、流水记“从谁那里听说什么”、可带短期情绪。设置页「本局人物」的「传播传闻」按钮出草稿弹窗，逐份确认后走 `applyNpcLedgerPayload(source='传闻')` 落账，流水标「传闻」；只认目标名单里的人。

**人物一致性体检（`npc/npc-consistency.js`）**：正文写完后的旁路小调用——拿在场人物档案（性格/说话/雷区/称呼/境界/伤势/态度方向）对照最近正文，只报「写违反档案的地方」（引正文原句作证据），不改档案、不拦正文。每次记账后自动查在场重要人物前 3 名（源 auto），设置页「一致性体检」按钮可手动全量查（前 6 名）；结果进审计 `npc_consistency` 与人物簿页体检卡。

## 纳戒（`self/`）

主角自身的总账，和人物簿（记别人）、世界台账（记世界）互不重叠：身份档案（姓名/性别/年龄/种族/出身/所属/天赋/外貌）、境界与段位（斗之气→…→斗帝）、金币、称号、功法、斗技、行囊（含装备中标记，同名同类别自动并账）、制作台（已掌握配方 + 炼制进度，按世界时钟倒数、显示超期）、目标约定（主线标星、达成退场）。

1. **唯一生成者：纳戒 API**。变量更新一律由纳戒决定生成（生成结束后调用 `self/self-decide.js`，读取最近聊天/相关设定/纳戒，输出 `{"note":"…","ops":[…]}`（≤12 条）），正文不再携带 MVU 申报块——世界书里的 `[mvu_update]` 申报教学条目由扩展在启动时无条件停用，旧 `self.mvuChannel` 通道选择（inline/正文申报）已整体退役，模型惯性吐出的申报块只当普通文本、不参与记账；纳戒变化改经 MVU 变量申报（`<UpdateVariable>`）进入，生成结束后由 MVU 仲裁器读帧差分、按业务规则裁决后入账。同楼重roll时决定读楼层基线快照，运行时 apply 会先撤销上一版贡献再应用新指令。`self.decideEnabled`/`self.decideAuto` 管决定启用/自动触发，关闭自动仍可手动请求。`self.guide` 与正文 `self` 指令解析是保留的兼容能力，不等于开启合并决定。`self.decidePrompt` 留空跟随内置默认；连接和喂料使用独立的 `self.decide*` 设置。
2. **操作集**：`setProfile`（八个身份字段）、`setRealm`、`setGold`/`addGold`、`addTitle`/`removeTitle`、`addTechnique`/`updateTechnique`/`removeTechnique`、`addSkill`/`updateSkill`/`removeSkill`、`addItem`/`updateItem`/`removeItem`、`addRecipe`/`removeRecipe`、`startCraft`/`finishCraft`、`addGoal`/`finishGoal`/`removeGoal`。
3. **注入**（`self/self-ops.js`）：生成前把纳戒现状写进独立注入通道 `doupo_self`，与世界、影响、人物簿、原著设定四路互不清空；超预算从目标、进行中炼制、行囊往上丢，身份与境界永远保留。
4. **脚本执行**（`self/self-runtime.js`）：越界数值、未知操作、超长文本只拒绝不炸；同楼重 roll 先撤销上一版指令再落新账；撤销恢复保留原编号且发号器同步前进；行囊扣到 0 自动移除条目。
5. **持久化**：整份纳戒存 `chatMetadata.doupo_agent_self`，随聊天保存，切聊天自动恢复。
6. **面板**：设置页「纳戒」按子页签分六页——基本信息（身份字段逐格手改、境界突破、金币、称号、流水）、功法、斗技、行囊（装备/卸下、改数量）、制作台（配方 + 开工/成丹/炸炉）、目标（立目标/达成/移除）。手动操作与模型决定走同一套校验，改完立即记进流水。
7. **所有权边界（防双写）**：世界时钟/事件/名声通缉归「世界运转」，NPC 档案与好感归「人物簿」，纳戒只记主角自己；决定提示词里同样写明不越界。

## 数据库桥接（`host/db-bridge.js` + `host/db-tables.js`）

可选把纳戒与记忆镜像到**「龙血玄黄·数据库」**（酒馆助手脚本，`window.AutoCardUpdaterAPI`）。**持久状态权威是各自的 `chatMetadata` ledger（随聊天保存的台账），数据库表和 MVU 帧不是独立真账本**：世界 `doupo_agent_world`、纳戒 `doupo_agent_self`、记忆 `doupo_agent_memory`、人物簿 `doupo_agent_npc`、冷藏推进 `doupo_agent_npc_cold`、世界影响 `doupo_agent_impact` 各归自己的运行时写入。**世界运转不连数据库**——时钟/事件/任务只跟世界台账走；旧版镜像过的三张世界表会在合并导入时从聊天模板移除。`enableDbBridge` 默认开启；关闭或未装数据库脚本时桥接调用跳过，不改变聊天台账的持久化路径。

- **表结构**（`db-tables.js`，12 张，uid 固定）：纳戒 10 张（主角档案、称号、功法、斗技、装备、天材地宝、行囊、炼丹、炼器、目标）+ 记忆 2 张（小记忆、大记忆）。桥接表的 `initNode/insertNode/updateNode/deleteNode` 都是「禁止操作。」，`updateConfig.updateFrequency=0` 配合 `uiSentinel=-1` 表示退出数据库 AI 自动填表；这是模板配置合同，不替代真实宿主验证。
- **模板自愈**：换聊天/启动时读当前聊天模板，缺桥接表就用 `importTemplateFromData` 以 `dataMode:'merge'` 补进当前聊天（每个聊天至多一次）。注意数据库脚本的 merge 导入是**整包替换**：外来表必须随包携带才不会丢；而它又按「DDL 注释 = 表头」逐列校验整包，所以导入前会把注释与表头对不上的外来表 DDL 按表头重建（`sanitizeForeignDdl`，表名/表说明/行内容/updateConfig 不动，桥接表永不改写）——外来表的行数据与结构不受影响，只是 DDL 注释被对齐；旧语义模板带 0=沿用UI 时不置新语义标记，避免误禁外来表的自动更新。
- **生成来源**：`agent/斗破Agent数据库桥接表.json` 只从 `host/db-tables.js` 的 `buildBridgeSheets()` 生成，含 12 张仅表头的空表、mate、「禁止操作。」节点与 updateConfig；小/大记忆 `exportConfig.enabled=false`，不含废弃的「已了结/了结日」列。仓库根目录执行 `node agent/doupo-agent-ui/tools/build-db-template.mjs`，写前结构自检；再用 `node agent/doupo-agent-ui/tools/docs-contract.test.mjs generated` 只读深比较完整对象。不要手改生成 JSON；表源变更归表结构 owner 单独审查。手动导入会改目标数据库模板，须另行确认作用域与备份；本次重新生成不是已导入、旧档迁移或真实宿主验收。
- **镜像**（写）：`persistSelf/persistMemory` 在存聊天档案后顺手镜像——先 `exportTableAsJson` 读最新表，reconcile 出最小差异（删除按原索引从大到小 → 逐行 updateRow → 追加 insertRow），桥接表按「编号」对行，编号为空的手工行不删不碰。
- **受保护收养**（兼容读入，不是表覆盖台账）：恢复聊天后及 `doupoAgent.dbBridgeAdopt()` 手动调用仍可读表。纳戒只接收有效更新时间且不早于本地的表状态（本地无档时也要求有效时间），保留流水与未映射字段；记忆仅在有新增/文本变化且编号未退役时合并，保留本地独有条目、退役编号与流水。空表不清账；过时聊天/飞行期间已变化的结果不会提交。通过护栏的结果仍经运行时写回 `chatMetadata`，不能拿镜像当作完整存档恢复源。
- **外部手改回拉**：`registerTableUpdateCallback` 去抖后仍走上述护栏，再保存聊天台账、刷新面板；桥内活跃写入期间屏蔽自身回调。表格手改不是无条件成功的正式记账入口；本次不移除或改写这条兼容路径。
- **冷聊天兜底**：CRUD 写入需要数据库在当前聊天已有楼层锚点；全被拒时自动改走 `importTableAsJson` 全量导入（锚定最新 AI 楼层），仍失败则记入桥状态、数据留在聊天存档不丢。
- **状态查看**：设置页「纳戒」卡底部的「数据库桥接」行（已连接/未检测到脚本/异常+原因），或 `doupoAgent.dbBridgeStatus()`。

注意：桥接表一旦建立，请勿在数据库脚本里改这 12 张表的表头或 DDL——列名与 `db-tables.js` 里的编解码一一对应（有单测锁定）；改列要走表结构 owner 的代码审查。

## 纳戒 → MVU 变量同步（`host/self-mvu.js`）

把主角档案/境界/金币及功法、装备、行囊、目标等投影到 **MVU（MagVarUpdate）的 `stat_data.斗破纳戒`**（顶层平键，整体覆盖），供状态栏、EJS 模板读取；剧情日仍归世界台账，不在此投影。MVU 帧不是持久状态权威；MVU 主脚本缺失/关闭时自动降级为酒馆助手原生楼层变量读写（`getVariables`/`replaceVariables`，帧结构一致），两层都没有才跳过。纳戒决定落账后由扩展把台账投影回帧；不能把申报帧直接当成真账本。

- **写入协议**：MVU 官方的「读帧 → 改帧 → 整帧写回」——`getMvuData({type:'message',message_id:'latest'})` 取该楼变量帧，改 `stat_data.斗破纳戒`，`replaceMvuData` 写回。不要用 `setMvuVariable` 做持久化：源码里它只改内存树、不落盘。stat_data 里别人的键原样保留，缺失的 stat_data 自动建。
- **触发**：`persistSelf`（纳戒决定落账/面板改动）与换聊天恢复后各同步一次；`doupoAgent.selfMvuSync()` / `selfMvuStatus()` 可手动触发与查看。
- **与数据库桥的分工**：纳戒真账本在扩展（chatMetadata），数据库表和 MVU 变量是两个并列的下游镜像；数据库脚本对 MVU 只有读（它把 stat_data 塞进自己的 EJS 上下文），写 MVU 的责任在扩展。
- **不启用 MVU 的"深度分析"**：那是让 MVU 另调一个模型从正文提取变量的可选功能；纳戒数据的更新走扩展决定＋代码投影，零额外模型调用。

## 记忆存储（`memory/`）

主角视角的记忆总账，与各账本所有权互斥（目标约定归纳戒、任务归世界、事件归世界台账、NPC 档案好感归人物簿、原著设定归事实库——记忆一律不碰，决定提示词里写死了这条边界）。**记忆是资产：永久保存、按需召回，脚本从不过期、不封顶、不自动丢弃任何记忆**，删除只由书记官或玩家主动做。分两层，按分量切而不是按寿命切：

- **小记忆**（`small`）：轻量记录的近事杂事，不必重要才记，保持主角"记得这几天发生过什么"；
- **大记忆**（`big`）：值得一直记住的事（恩怨/秘密/伏笔/大事），召回优先级更高；`tag` 是可选标签（恩怨/情报/伏笔/大事记），只便于查看；
- **转大**（`promote`）：小记忆分量够了转成大记忆。
- **召回钥匙**：`related`（1-4 个人名/地名/物名）必填——没有钥匙的记忆永远召不回来，运行时直接拒绝。

1. **决定调用**（`memory/memory-decide.js`）：世界决定结束后的回调会启动影响、纳戒与记忆各自的后台链，但不等待前两条全部完成，不能承诺记忆读取到它们当轮的新账。记忆决定读最近聊天、相关设定与本场召回记忆，输出 `{"note":"…","ops":[…]}`（≤12 条）逐条校验；`memory.decideAuto=false` 停止自动决定，仍可手动调用，正文 `memory` 指令解析作为兼容入口保留。连接与喂料使用独立的 `memory.decide*`；`memory.decidePrompt`/`memory.guide` 留空跟随内置默认。
2. **操作集**：`remember`（小记忆）、`memorize`（大记忆，模型通道自动降为 remember）、`promote`（仅面板手动）、`forgetMemory`（记错删除）、`supersede(id, by)`（软覆盖：旧记忆被本轮新事明确覆盖时标记，恢复由玩家做）；公共字段 title 必写≤14字（列表主页只显示标题）、text≤300、basis 必写≤80、related 必写≤4、quote≤60（当时的一句原话，召回时以「」带回）、note≤200（细节补充）、weight major|minor、importance 可选 1-10（写入时重要度评分，Generative Agents 检索三因子之一：大事/恩怨/伏笔 7-10，日常 2-4，不写按分量推默认 关键7/一般5）。**写入时查重**：同层同文不重记之外，与共享钥匙的同层在用旧账词面相似 ≥0.85 的新条目直接拒绝（`duplicate_of_mN`，MemPalace check_duplicate 思路）——近似重复在写入时拦住而不是事后体检；跨层同文不受查重影响（分层升级是合法路径）。**账本无上限**，脚本从不自动清理。
3. **召回决定与注入**（`memory/memory-recall.js` + `memory/memory-retrieve.js`）：用户输入之后、生成之前，把**记忆目录（编号|层|标题|钥匙）+ 最近聊天（含最新玩家输入）+ 世界书命中**交给召回模型，挑出本轮要注入的编号（≤25 条、按相关度排），脚本按编号取条目注入独立通道 `doupo_memory`；结果按楼缓存，重 roll 不重复调用。**目录与兜底共用一套混合检索打分**（`memory-retrieve.scoreEntries`，确定性零网络）：召回钥匙命中（+2.5/把，封顶 +5）＋引文原句回响（+3）＋标题命中（+1.5）＋bigram 词面包含（同义改述也能勾到，封顶 +2.5）＋世界时间邻近（45 天线性衰减，封顶 +1.5）＋重要度偏离中值分量（每档 ±0.15，关键旧账天然排前）＋可选语义相似度（封顶 +4），大记忆与关键分量作底分；**只有场景信号真正命中（triggered）才算"勾到了"**，纯底分不凑数。目录按分数序排（超预算从尾部丢，`memory.catalogBudget` 可调），召回模型自上而下读；**召回失败/关闭 → 兜底**（`memory-ops.recallHits`）走同一套分数，只取 triggered 条目注入。`findMemoryConflicts` 用 bigram Dice 在同钥匙记忆里找疑似重复/矛盾（已软覆盖的不再报），面板标 ⚠ 只提醒不拦账。总结大记忆继承原小记忆的最高重要度。
4. **脚本执行**（`memory/memory-runtime.js`）：越界数值、未知操作、缺 related 只拒绝不炸；同楼重 roll 先撤销上一版指令再落新账；opId 去重防重复喂入。
5. **持久化**：整份记忆以 `chatMetadata.doupo_agent_memory` 为权威；数据库桥接开启时镜像到小记忆/大记忆两张表（引文/别名，标签仅大记忆）。换聊天与外部手改仍保留受保护收养，但记忆按内容与退役编号合并，纳戒按更新时间判断；两者护栏不同，均不代表镜像表优先（见「数据库桥接」）。
6. **软覆盖 supersede 与有效性**：书记官在本轮正文明确续写/覆盖某条旧记忆时可输出 `supersede(id, by)`（by=本轮新记的记忆编号），脚本校验两条目都在账、不自指、不成环；被覆盖的旧账**默认不再进召回目录与注入、不进矛盾提醒、不进总结批**，但账本里永久保留，面板行内点「恢复」（`unsupersede`，仅玩家手动）随时找回。覆盖者被删除/随楼删除/被总结退役时，指向它的标记自动清空（引用完整性）；坏档里的悬空指针在 restore 归一化时原地清理。
7. **语义检索（可选，默认关）**：「模型设置」页的**语义检索卡**填 OpenAI 兼容 `/v1/embeddings` 端点（`memory.embedding.{enabled,baseUrl,apiKey,model}`，不走酒馆连接、不绑 API 方案）即启用——落账后后台按 hash 差异化补嵌（`memory-vectors.js`，向量按聊天存浏览器 IndexedDB，改文本/换模型自动重嵌），召回与兜底在混合打分外叠加余弦相似度（≥0.35 起评，封顶 +4）。没配置/失败一律静默退回纯本地混合检索，零行为变化；统计行显示"已向量化 x/y"，卡上可一键重建本聊天向量。
8. **按人整合视图（时间线）**：记忆页「按人整合」弹窗——选一个人，`memory/person-view.js` 把他散在三本账里的叙事并成按世界天新→旧的时间线：记忆（关联/别名钥匙与档案名双向包含命中，已替代的带标记仍在场）、人物簿**好感流水**（`favorLog`，此前没有任何 UI 呈现）、经历、流水、世界事件（名字出现在标题/正文/依据里）、任务（进行中/已完结）。人物簿没建档时退回记忆关联钥匙；行首角标标来源，最多铺 60 条，档案摘要在顶部一行。
9. **记忆体检卡**：记忆页「记忆体检」——纯本地统计（`memory/memory-audit.js`，不发模型调用）：疑似矛盾对（复用 `findMemoryConflicts`）、**孤立钥匙**（只被一条在用记忆引用、且人物簿/世界台账里认领不到对应实体，多半是笔误，改那条记忆的关联/别名即修）、**目录覆盖率**（当前 `memory.catalogBudget` 预算下召回员实际可见 x/y，装不下就提示调预算）、已覆盖条数；向量覆盖仍在「模型设置」页。
10. **开局摘要（wake-up）**：切换/载入聊天后的**第一条回复前**，`memory/memory-wakeup.js` 把时间·季节·地点、在场人物（重要的带 ★）、待办任务、未了线头（伏笔标签）、旧账恩怨（恩怨标签）整合成一次跨账本交底，注入独立通道 `doupo_wakeup`——**只注一次**（门闩按聊天号武装：启动恢复与每次 CHAT_CHANGED 各武装一次，命中即销），生成结束与换聊天即清。`memory.wakeUp` 开关与 `memory.wakeUpBudget`（200-2000）在「记忆注入」卡；空库空账返回空串，本轮不注。
11. **面板**：设置页「记忆存储」——总览、**记忆体检卡**、**记忆注入卡**（最近一轮实际进入提示词的记忆：来源/条数/字数/时间，点条目看完整记录；含开局摘要开关与字数上限）、**排序切换（按生成时间 / 按分量 / 按标签分类）**、**按关联过滤**（下场对手戏前按人扫旧账）、大记忆/小记忆两栏清单（转大/提关键/删除/恢复、引文与别名展示、重要度展示、⚠ 矛盾标记、已替代标记、详情弹窗含**相关记忆共钥匙跳转**可连环点看）、手动登记（层级+标签+关联+别名+引文+备注）、召回开关与预算、**目录字数上限**、决定/召回两套开关、两份提示词改写、指令流水、**按人整合弹窗**；语义检索卡在「模型设置」页。手动操作与模型决定走同一套校验。悬浮球记忆面板同款：摘要带「本轮注入了 N 条」，头部是**已注入的记忆**列表（点开详情），记录随聊天存档走、生成结束自动标「已清理」。
12. **命名空间**：`doupoAgent.memoryStatus()/memorySnapshot()/memoryApplyPersisted()/memoryDecide()/memoryRecall()/memoryRestoreFromChat()`。

### 记忆召回与数据库表（绿光条目默认关闭）

记忆召回由扩展自己的**召回决定**负责（见上）：注入预算与挑选逻辑都在扩展侧。小/大记忆表保留 **`exportConfig`（导出配置）** 形状，但 `enabled:false` 默认关闭，避免扩展注入与数据库条目重复进入提示词。这不是面板可选召回模式；若另行改为数据库召回，必须由 owner 单独评估注入去重与预算，不能只翻开关。以下仅解释保留的配置：

- **触发词** = `关联,别名` 两列（逗号分隔的列名）；行里这些列的值再按逗号切成一个个触发词，人名/地名出现在最近楼层就整行注入。
- **注入模板**：小记忆 `<记忆近事>$1</记忆近事>`，大记忆 `<记忆存储>$1</记忆存储>`。
- **关联/别名列用逗号连接**（数据库的触发词拆分只认 `,` `，`，不认顿号）；扩展台账内部仍是数组，读取时兼容顿号旧行。
- 配置跟着表格定义走（`db-tables.js`），数据库脚本一行不改；桥同步时同表同表头但导出配置对不上会原位刷新（算 `updated`）。

### 楼层显示美化（`host/display-regex.js`）

数据库召回会把用户楼层原文改写成「以下是用户的本轮输入 + `<本轮用户输入>`正文 + 召回导语 + 时间约束词表」，纯文本裸奔在楼层里。扩展启动时往酒馆正则扩展的全局列表注册四条**仅格式显示**的正则（`markdownOnly=true`、`runOnEdit=false`），只改渲染：存档原文不动、提示词不受影响、编辑楼层看到的仍是原文。

- **输入段空行守护**：输入段内的空行压成单换行——markdown 的 HTML 块遇到空行会截断，卡片会散架。
- **本轮输入卡片**：输入段包成 `.dpz-round` 卡片（简约玄幻：细金线 + 四角符箓 + 淡金底晕，样式在 `host/style.css`；酒馆会给楼层里的 class 加 `custom-` 前缀，两组选择器都写全）。
- **召回导语收纳**：从「以下输入的代码为既定事实记忆…」起整段收走——那是提示词的家什，玩家没必要在楼层里看。
- **旧楼层隐去**：屏幕上只留最近三楼。给每一楼开头钉一个空帷幕标记 `.dpz-floor-veil`（内容原样保留，用户楼与 AI 楼都钉），收不收由 `host/style.css` 按位置动态决定——带标记又不在 `#chat` 最近三块里的整楼 `display:none`。不按渲染时刻算深度：酒馆出新楼**不会重渲染旧楼**，按深度清空会让“留几楼”越漂越远；按位置算，新楼追加、删楼、插入都自动重算，永不漂移。要改保留楼数就改样式里两处 `-n+3` 的 3；想看全史，正则面板关掉这条脚本再重进聊天即可。
- 同名脚本已存在一律不覆盖（正则面板里可见、可改、可关，用户手改的为准）；首次补装后自动 `reloadCurrentChat` 让老楼层立即生效。

### 已退役兼容：合并决定

合并决定不再是可启用的运行模式：`self.decideMerged` 是迁移时清理的旧键，`unifiedActive()` 恒为 `false`；保留的 `doupoAgent.unifiedDecide()` 只返回 `{ status: 'retired' }`，不发模型请求、不提交纳戒或记忆操作。`unified/unified-decide.js` 的纯解析函数留作兼容，不代表入口仍在运行。

- 纳戒变量更新一律由纳戒决定生成（绑定 `self.decideApiPreset`），记忆决定绑定 `memory.decideApiPreset`；记忆总结沿用记忆连接，两域不再共用合并开关；正文 MVU 申报通道已退役。
- `cited` 已不再有消费方，`recallCount`/`markRecalled` 也不是当前记忆合同；召回由独立召回决定及关键词兜底负责。
- `writeMemoryInjectionForPrompt` 依 `enableMemoryLedger`、`memory.inject`、`memory.recallEnabled`、`memory.recallAuto` 选择禁用/召回/关键词兜底，不因旧合并键委托给数据库。保留兼容 API 不等于恢复旧功能。

## 开放世界（`sandbox/`）

`enableSandboxMode` 打开后（正式口径记录以 `sandbox-mode.js` 为准，中途切换要确认），世界换成**开放的斗破苍穹主世界**——不跟随原著剧情，原著故事不是日程表；方向不单设，世界运转的任务与传闻就是递到玩家手里的方向：

- **不用世界书**：原著设定注入与设定挑选整条停用（`getSettingBudget` 直接返回 null，设定挑选的模型调用也省掉），正文注入通道改写内置**斗气大陆基线**（`sandbox/sandbox-world.js` 的 `SANDBOX_WORLD_PROMPT`，以世界书常驻体系条目为底稿：斗气阶梯/功法四阶/炼药师/异火榜/魔兽魔核/中州格局）。
- **决定喂料换血**：世界决定不再带世界书条目，改带 `SANDBOX_DECIDE_NOTE` + 斗气大陆基线；纳戒/记忆/合并/影响/记录员的决定喂料在开放世界下一并停用世界书条目。远地的事按既有契约走 `rumor` 传闻事件（查证后 `resolveEvent` 了结），不新增系统。
- **总控可见**：总控页「运行口径」卡显示当前口径与正式记录状态；原著设定页的「上次注入」在开放世界下显示的就是斗气大陆基线。
- 玩家目标、目标上限等设置不单设——目标就是世界任务（`world/`），开放世界只是不再替玩家排剧情。

## API设置（接口方案）

设置页「核心能力 → API设置」把每套接口配置存成命名方案（最多 20 个）：名称、协议（自动判断/OpenAI 兼容/Anthropic）、接口地址、API Key、模型（可点「拉取模型」从列表选）、采样参数（温度/最大输出/top_p/两个惩罚项，0 ＝不指定），以及与酒馆「自定义接口 · 附加参数」同语义的三段附加参数——**包括主体参数**（YAML 对象，最后并进请求体，例 `top_k: 20`）、**排除主体参数**（YAML 数组，最后从请求体删顶层字段，例 `- frequency_penalty`）、**包含请求标头**（YAML 对象，合并覆盖请求头、可覆盖鉴权头）。酒馆是服务器端用 js-yaml 解析这三段，扩展在浏览器里直连，所以自带一个覆盖酒馆文档全部示例用法的迷你 YAML 解析器（`host/api-presets.js` 的 `parseYamlBlock`，JSON 直接透传）。方案只保存在扩展设置里（密钥也是，与 `llm.apiKey` 同口径，不进聊天消息）。

## 模型设置（只选方案）

「模型设置」页每张卡只回答一个问题：这个功能用哪套方案（schemaVersion 11 起）。15 个绑定键——全局连接/原著设定/行动结算分类/行动结算最终判定/世界决定/记录员/**档案抄录**/**经历精简**/冷藏推进员/**纳戒决定**/**记忆决定**（合并决定已退役，这是两条独立调用：各绑各的方案、各喂各的楼层）/**记忆召回**/**记忆总结**/世界影响记录员+场记，统一存 `*.apiPreset`/`*.decideApiPreset`。**不绑方案＝跟随酒馆主连接**；绑了方案，该功能的每次调用整套走方案（接口、参数、附加参数按酒馆同序套用：先并主体、再排除、标头最后覆盖）。旧的每卡手填字段（模式选择/地址/密钥/模型/采样参数/每卡拉取按钮）已全部删除；升级时 host-storage 的 `migrateLegacyApiPresets` 把各卡 `mode=custom` 且填了地址的旧配置一次性搬成方案并自动绑定（字段完全相同的卡去重共用一个方案，搬完该组 `mode` 落回 tavern，重跑无事可做，删掉的迁移方案不会复生）；v11 拆分把拆分前“纳戒与记忆共用”的绑定与喂料复制给纳戒做起点（版本门只跑一次，之后两侧各改各的）。场记不绑方案就跟着记录员；档案抄录/经历精简的任务级温度与上限补丁仍叠在各自方案之上；删除方案时指向它的功能自动回到跟随酒馆主连接；`self.decideMerged` 死开关随合并决定退役一并清理。跟随酒馆路径（`generateQuietPrompt`）没有附加参数落点，方案仅作用于自定义接口直连。跟随酒馆时采样参数不再单独指定（沿用酒馆/全局自己的设置）；要参数就在「API设置」页建方案。

## 调用版本：完整版 / 简略版 / 进阶版（schemaVersion 14 起）

「模型设置」页顶部的**调用版本**卡三选一，`apiMode` 决定每轮跑哪条管线：

- **完整版**（`full`，默认）：每个功能各一路调用，行为与旧版一致；进阶增强整体关闭。
- **简略版**（`lite`）：备料三路并成一次「素材总挑选」、记账五路并成一次「总结算」，一轮最多 3 次模型调用；进阶增强整体关闭。
- **进阶版**（`advanced`）：完整版逐路管线，再叠上全部 **GitHub 系增强**——难度骰子+变数 Oracle+结构化代价、正文核验（VeriScore 三标签）、人物一致性体检、人物关系网二跳注入、开局摘要（wake-up）、剧情账本决定、语义向量检索。这些功能只有进阶版生效（各功能自己的开关仍然生效，进阶版只是放行的总闸），切回完整版/简略版整体静默，设置页的对应卡片也随之隐藏。

显隐机制：`data-api-mode-section`（空格分隔多版本）+ `renderApiMode` 成员匹配——完整版连接卡对进阶版共用（标记 `full advanced`），进阶专属卡（正文核验/剧情账本/一致性体检/关系网/传播传闻/开局摘要/骰子开关/语义检索/记忆体检/按人整合）标记 `advanced`，每次切页与切版本重算。升级迁移（v11-13 且非简略版的既有安装自动落进阶版，全新安装默认完整版）。决策喂料统一带【本轮行动结算】节：结算判过的成败（含骰子结果与文字后果）喂给世界/剧情/纳戒/记忆/影响决定与简略版总结算，决定链照判定记账，不许照玩家输入想当然；功能调用读楼层先剥 `<thinking>` 幻括号再套角色正则（`host/floor-text.js`），头部截断不再被思维链占满。

## 三个宿主适配器

- **模型**（`host/llm-client.js`）：连接方式二选一（`llm.mode`）——跟随酒馆当前 API（`generateQuietPrompt`）或自定义接口；自定义接口支持 OpenAI 兼容（`/chat/completions`）与 Anthropic 兼容（`/v1/messages`，`x-api-key` 鉴权、system 独立字段、content 文本块拼接）。旧版只有 `useSillyTavernConnection` 开关的配置会按老开关自动迁移到 `mode`。没配好时这一轮直接返回“模型连接未配置”，不会静默跳过。**失败详情**：非 2xx 响应会读响应体提取服务商的真实原因（JSON 的 error.message/code/type，非 JSON 用原文片段），错误文本与体检条目带 `HTTP 状态码（POST 端点）：原因`，响应体里若回显密钥自动打码；控制台同步输出完整详情。酒馆连接路径受 ST 限制——它只抛裸错误（常常只有 "Bad Request"），体检条目只能标「酒馆连接」定位是哪次调用；要响应体级原因，把对应功能绑到自定义接口。
- **消息**（`host/message-adapter.js`）：用 `createChatMessages` 把正文写进当前对话，再回读聊天列表确认最后一条就是它；确认不到就不提交状态。
- **存档**（`host/state-persistence.js`）：状态、历史与版本号存在 `chatMetadata['doupo_agent_state_v1']`，按会话与分支隔离，切换聊天会重新载入。

## 怎么用

- 设置面板“总控”页点 **结算这一轮**：取当前对话里最后一条玩家消息，跑完整条链并在面板里显示结果。

## 数据合同

`doupoAgent.contracts` 登记对象、字段、类型、唯一写入者和允许读取者，开局自带 `player` 与 `world` 两张表。质量门只接受已登记字段的写入，写入者必须与该字段登记的 writer 一致，所以模型编出来的字段（比如 `player.luck`）会被直接拒绝，而不是悄悄写进状态。

## 主要接口

- `doupoAgent.runTurn({ sessionId, branchId, input, triggerMessageId })`：跑一轮，返回 `completed / needs_clarification / rejected / failed / save_uncertain / disabled / unavailable`。
- `doupoAgent.inspectTurnState({ sessionId, branchId })`：读当前状态与版本。
- `doupoAgent.pipeline` / `doupoAgent.stages` / `doupoAgent.orchestrator`：直接使用管线、阶段或编排器。
- `doupoAgent.router` / `doupoAgent.quality` / `doupoAgent.narrative` / `doupoAgent.commits`：路由、质量门、叙述门与提交恢复。
- `doupoAgent.facts` / `doupoAgent.actions` / `doupoAgent.world` / `doupoAgent.npcs` / `doupoAgent.sandbox`：资料、行动、世界、NPC 与沙盒能力。
- `doupoAgent.npcLedger` / `doupoAgent.npcLedgerRecord()` / `doupoAgent.npcLedgerApply(patch)` / `doupoAgent.npcLedgerExtract({ names, overwrite })` / `doupoAgent.npcLedgerSetPlayerContext(fn)` / `doupoAgent.npcLedgerStatus()`：人物簿的查、记、手填、按世界书重抽、玩家处境接线与控制台状态。
- `doupoAgent.npcColdRuntime` / `doupoAgent.npcColdSelect(name)` / `doupoAgent.npcColdDeselect(name)` / `doupoAgent.npcColdPreview()` / `doupoAgent.npcColdConfirm(id)` / `doupoAgent.npcColdDiscard(id)` / `doupoAgent.npcColdStatus()`：冷藏人物选择、扫描草稿、确认写回、放弃草稿和状态查看。
- `doupoAgent.selfRuntime` / `doupoAgent.selfApply(ops, { floor, day })` / `doupoAgent.selfDecide()` / `doupoAgent.selfApplyFromLatestReply()` / `doupoAgent.selfStatus()` / `doupoAgent.selfSnapshot()` / `doupoAgent.selfJournal()`：纳戒的运行时、手动落账、手动决定、正文指令块解析、状态与流水。
