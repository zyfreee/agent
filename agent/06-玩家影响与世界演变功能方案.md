# 06 · 玩家影响与世界演变功能方案

版本：v1.0（功能设计基线）
日期：2026-10-21
状态：用户确认方向并授权保存；仅设计，未实现或酒馆实测。实现字段和测试方案为建议。

## 1. 目标与职责

玩家已经做过的事情，应持续改变后续故事线、任务、地点、势力与世界条件，而不是只有当轮文字不同。第六模块替代已撤回、未保存的“剧情与叙述”草案。

不把所有世界变化都归因于玩家，不让全世界无条件围着玩家转。影响必须有依据、范围、传播条件和时间。

- 行动结算：产生一次行动的直接结果和代价。
- 本模块：从已确认事实检查后续前提，提出跨系统影响和路线调整。
- 世界运转：按改变后的条件推进时间、资源、既定过程与局势。
- 总控：安排调用及协调提交；状态与长期记忆：保存正式事实与历史。

不直接写存档，不替玩家选择，不决定具体NPC重大意愿，不暗中恢复搁置的第三模块。普通正文仍由主生成环节呈现，不新增独立叙述Agent。

## 2. 六项功能

### IMPACT-01 定位受影响对象

从已确认行动、事件与现有关系查找人物、故事线、任务、地点、通路、设施、势力、资源及后续过程。脚本定位已记录依赖，LLM补充语义关联候选；新发现关系不自动视为事实。

只记录真正参与玩法的对象，不要求先建整个世界的复杂关系图。

### IMPACT-02 区分确定性与生效条件

分别记录确定影响、条件性影响、推测性影响，以及立即或延迟生效。确定性与发生时间是不同维度：确定将发生不等于现在已经发生。

例如据点被毁、消息传出、身份暴露、被通缉不是同一件事。条件性影响须等有效条件成立；推测不能直接改正式状态。具体人物决策缺失则返回待决定。

### IMPACT-03 调整故事线与任务

检查原有内容是否保留、改变进入条件/目标/完成方法、延后、完成、取消或提出新分支。向原著模块获取依据，本模块判断本局前提，不让资料模块推演世界。

玩家提前找到失踪者后，不应重复发布相同寻找任务。护送等后续必须有依据，不能为了续任务随意加阴谋。保留已取得进展与已结算奖励记录，任务调整不自动清零或重复发奖。

原著不自动是必经路线；是否保留指定节点待用户决定。不能抹除玩家已提交影响以强拉回原结局。

### IMPACT-04 改变地点与势力条件

地点可涉及通路、设施用途、安全条件、可达区域；势力可涉及资源、控制范围、合作条件、计划前提和机会。

本模块提出结构或条件调整，不重复扣除行动结算已扣资源。判定“原计划不可执行”不等于宣布“首领决定投降”。跨系统变化依赖的个人决定必须明确留缺口。

### IMPACT-05 保留因果并限制连锁范围

重要变化记录：玩家行动 → 已确认直接结果 → 改变的前提 → 受影响对象与后续变化。能回答任务为何消失、地点为何变化。

每一层推演须有依赖或新依据，不凭蝴蝶效应无限展开。限制对象数、层数、模型预算及停止条件，具体阈值经样本确定。超出预算保留未处理范围，不能假装全世界均已检查。循环依赖不反复施加同一影响。

### IMPACT-06 累积、修复与反作用

支持多次小行动改变条件，以及修复部分旧影响。累积须有明确记录，不凭模型印象加减状态。

修桥恢复通行，不抹除已经延误的运输；归还物品不自动恢复信任。区分恢复的条件、仍保留的历史后果和待决定的人物反应。

## 3. 与世界运转的交接

玩家导致的跨系统前提变化和故事线适用检查由本模块牵头。世界运转不另起一套相同因果推演；它执行新条件下的持续过程，并报告条件何时达到。

例：行动结算确认桥梁损毁；本模块定位受影响路线、运输与相关任务，提出条件调整；世界运转实际暂停运输并按时间处理库存。库存扣减只在其正式负责模块发生一次。本模块不同时预扣未来库存。

世界自身变化仍由世界运转负责。若它导致故事线前提变化，可以经总控调用本模块检查适用性，但来源标为世界事件，不能伪称玩家造成。

同一个后果约定唯一负责模块、来源事件与处理标识。确定影响与依赖它的条件调整按总控合同一致提交，后续轮次处理引用已提交版本，避免每轮来回循环调用。

## 4. 脚本与LLM

脚本：已知依赖查询、条件/时间检查、变更对照、版本与重复检查、待生效条件管理、预算限制。

LLM：理解社会与剧情含义，提出有限间接影响、合理分支及依据，指出不确定性。不执行任意代码、不绕过个人决定、不把候选当历史。

无相关变化不必调用模型。规则能处理时优先脚本，不要求每个受影响对象独立模型调用。

## 5. 工作流程与交接建议

接收已确认行动或事件 → 查找关联对象 → 检查前提 → 必要时提出有限间接影响 → 区分确定/条件/推测 → 检查冲突、来源、决策缺口与范围 → 返回总控 → 状态模块保存 → 世界运转按新条件继续。

输入建议：会话/分支/行动或事件标识、起始状态版本、已确认事实、关联对象与过程、原著依据、玩法约束、已有影响记录、处理预算。

输出建议：受影响对象、变化前后条件、影响确定性、生效时间与条件、依据与因果链、负责模块、变更提案、待决定项、未处理范围、可观察条件。

实际世界变化与玩家知情分开，不把后台后果直接公布。精确字段、存储与API未冻结。

重复请求不重复施加影响；过期候选不得覆盖新状态；取消、部分提交、回退和分支沿用总控及状态模块合同。不能只回退状态而保留未来影响队列。缺证据返回未决，不伪造完整推演。

## 6. 待执行验收

1. 提前完成目标后，旧任务调整而不是重复发布。
2. 重要前提变化后，相关故事线改变，不强拉回原著。
3. 地点关闭持续有效，下一轮不无故恢复。
4. 条件性后果在条件成立前不生效。
5. 推测性影响不污染正式状态。
6. 同一资源与后果不会被多个模块重复计算。
7. 能追溯重要变化的来源与中间依据。
8. 多次行动可累积，重试不被当成新行动。
9. 修复恢复条件但不抹除历史。
10. 缺失NPC重大决定时明确等待，不编造决定。
11. 分支与回退隔离未来影响，过期版本被拒绝。
12. 连锁推演有界且报告未处理范围，不把非玩家变化归因于玩家。

以上为待执行测试，不代表已通过。先验证一个行动同时影响任务、地点和既有过程，再检验延迟、修复与重复处理，不以完整世界模拟作为首版前提。
