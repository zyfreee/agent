# 04 · 世界运转功能方案

版本：v1.1（与第六模块职责同步）
日期：2026-10-21
状态：用户同意保存世界运转方向；仅设计，未实现、未做酒馆实测。下述实现建议和验收细节可继续修改。

## 1. 目标及明确修订

在酒馆脚本＋LLM Agent 系统中，让世界随游戏时间和实际行动持续变化。不是只检查预设事件是否触发，而是推进地区、资源、组织过程及社会变化，由变化产生事件和玩家可以介入的机会。

用户否定仅以事件判定为重心的旧方向，采用世界运转。事件条件检查保留为内部工具，不是模块核心。原著资料模块只提供证据，不推演本局。

第三模块暂时搁置：原角色群像草案已撤回，后续“单独聊天＋NPC 自主决策”仅为候选，尚未定稿。本模块不吸收个人 NPC 的自主决策，不预建第三模块文件。

## 2. 职责与边界

负责统一规则下的世界时间推进建议、地区条件、资源流通、既定组织计划、公共活动、消息传播过程以及局势变化。根据经过时间与已确认行动生成有依据的世界变化提案。

不负责玩家选择、个人 NPC 重大决策、单次具体行动胜负、完整剧情正文、原著证据维护和正式状态存储。调用由总控管理，正式状态由状态与长期记忆模块保存，不建立另一份世界存档。

世界模块可以提出组织层面发展建议，但结果依赖具体人物重大选择时必须请求对应决策；该能力未接入时标为待决定，不能伪装为已发生。内部计算候选变化不等于直接写入存档。

## 3. 五类运转对象

| 类别 | 内容 | 对玩家的影响 |
| --- | --- | --- |
| 地区与环境 | 昼夜、季节、天气、道路与可达性 | 时间和地点改变行动条件 |
| 资源与流通 | 补货、消耗、运输、供求 | 断路可造成缺货，库存不是无限 |
| 势力与组织 | 已定计划、资源投入、控制范围、竞争局势 | 组织不永远停留在开局 |
| 公共活动与秩序 | 集市、拍卖、招募、巡查、封锁 | 活动有准备、进行、中断和结束 |
| 消息与公共认知 | 信息来源、渠道、传播范围和延迟 | 远方事件不瞬间人尽皆知 |

这五类是整体候选范围，不代表首版全部实现或所有作品都必须具有完整经济、气候模拟。只对真正影响玩法的内容建规则。消息传播到地区不等于某个人已经知情；具体接收通过相关事件和状态流程确认。

## 4. 核心功能

### WORLD-01 推进游戏时间与持续过程
接收总控明确提供的耗时、目标时间或经过确认的行动结果，按统一游戏时间推进。现实等待模型的时间不自动进入游戏时间；对话、旅行等如何计时后续制定。

延续已确认过程，如运输、建设、产出和封锁。不每轮重新让模型决定这些过程是否存在。并行活动按实际时间区间处理，不把同一时段重复累加。

跨过多个关键节点时按依赖顺序处理，不能一次跳到终点漏掉中途消耗或暂停条件。遇到需要玩家决定的节点按既定介入规则暂停或分段，不替玩家选择。

### WORLD-02 根据条件产生变化
已有规则可计算的变化交给脚本；需要理解局势的部分交给 LLM 提出有限候选。每项变化须有当前状态、规则、实际事件或经确认计划支持。

例如商路切断→补货延迟→库存逐步减少→供求变化。替代路线、求援等是可能的新方案，未检查资源、条件或必要决策前不记为已执行。不会为了制造戏剧性无依据生成灾难。

### WORLD-03 推进已有过程间的依赖
明确连接天气、交通、物资、组织计划、秩序等持续过程，只推进当前时间范围和既定预算内的依赖。玩家造成的跨系统前提变化由[玩家影响与世界演变](<06-玩家影响与世界演变功能方案.md>)牵头分析；本模块按已确认的新条件推进，不对同一行动另外推演一遍影响。

例如路线关闭后，本模块处理运输暂停和按时间产生的库存变化，不重复扣除行动结算已处理的资源。世界自身变化仍由本模块负责，来源不伪称玩家行动。循环影响不能导致无限推演，同一后果明确唯一负责模块与处理标识；尚不确定的后果保留候选。范围、批次和停止条件经样本确定。

### WORLD-04 交接故事线适用检查
本模块发现既有事件或过程前提改变时，经总控交给第六模块检查故事线、任务和原著事件的本局适用性；原著模块只提供证据。第六模块提出延期、取消或新分支，本模块执行已确认的时间与过程安排，不再独立维护另一套路线调整。

原著事件可作为参考模板，不自动成为必经剧情。作者是否保留特定必经节点、如何处理其与本局事实的冲突，尚待明确。不得暗中抹除已提交的玩家影响。

### WORLD-05 玩家未参与时继续运转
已建立的公开活动、资源过程和计划可以按规则持续推进，不永久等待玩家触发。明确区分可自行推进的普通变化与需要给玩家介入机会的重要节点。

不因追求真实而强行在后台结束所有重大剧情；也不因玩家未在场就冻结全部世界。具体介入规则待用户确定。

### WORLD-06 按相关程度分配计算
建议“当前地区细算、相关远方按节点更新、暂不相关地区概要推进”。玩家接近地区或相关事件发生时补齐必要细节。

补齐只可使用已有事实未限定的空间，不得追溯改写玩家已知历史、已提交记录或已结算资源。不同精度必须引用同一状态版本，避免商队跨地区时重复产货、重复消耗。没有有效变化时不调用 LLM。

### WORLD-07 形成世界结果与观察条件
返回哪些过程继续/暂停/结束，哪些地区、资源或组织状态改变，产生哪些事件与机会，变化依据和下一更新时间/条件。

区分实际世界变化、可能后果、可观察线索及未公开信息。提供发生地点与观察条件，不直接把后台秘密写入玩家正文，不直接改个人知情记录。具体呈现交给主生成环节，总控负责按范围交接；不再设置独立“剧情与叙述”模块。

## 5. 脚本与 LLM 分工

脚本：时间与数量计算、既定条件判断、过程推进、版本与重复检查、关联范围定位、输出结构和预算约束。

LLM：对没有确定规则的局势进行判断、提出发展候选、指出影响与缺失依据。它不能执行任意代码，不能绕过资源限制、个人决定或玩家介入门。

不是每个地区或每个时段单独调用模型。总控设置调用与重试上限，世界模块只返回必要的任务需求。模型推演并非客观真相，需经规则、来源与实际试玩检验。

## 6. 工作流程

总控传入游戏时间变化和已确认行动结果
→ 读取当前分支、世界状态版本及已建立过程
→ 定位需要更新的地区、时间节点和依赖
→ 脚本推进确定性规则与已确认计划
→ 为必要局势请求有限 LLM 推演
→ 检查时间、资源、前提、个人决策缺口及影响范围
→ 返回世界变化、事件、观察条件与下一更新节点
→ 总控协调提交，状态模块保存。

中途发现重大缺失、冲突或不支持的决策，返回部分候选或待决定，不能隐瞒跳过后宣布全部成功。总控决定是否允许部分提交；相互依赖的变化不能拆成矛盾状态。取消、回退、过期版本及恢复沿用总控与状态模块合同。

## 7. 交接规格建议

输入：任务/会话/分支标识、起始状态版本、起止游戏时间、已确认行动及事件、相关地区、已有过程和计划、玩法规则、原著查询结果（需要时）、计算范围与预算、玩家介入规则。

输出：所依据版本和处理时间区间、状态变更提案、过程进展、依据与因果关联、候选或待决定项、事件与机会、可观察条件、下一次更新节点、未处理范围和错误。具体字段并非现成酒馆 API。

示例：桥被破坏并确认不可通行，运输在桥前中断。若没有获准的绕行计划，只返回“运输暂停、补货推迟”；不擅自让商队领队决定冒险绕行。等待期间按有效规则消耗既有库存；产生缺货趋势后，LLM 可以提出相关局势候选，但不虚构商人已作出的决定。

## 8. 制作顺序建议

先选一个地区、一条运输过程、一项公共活动，贯通时间推进、明确资源变化与保存；随后验证中断、重复请求和玩家介入；再加入一次有界的局势推演，最后扩展跨地区依赖和远方概要更新。

这是建议的小样本验证路径，不是整体首版范围冻结。首版不能以全世界模拟为开工前提，也不能悄悄删去已确认的世界运转目标。

## 9. 待执行验收

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| W01 | 时间推进 | 按游戏时间运转，不跟现实请求耗时走 |
| W02 | 并行过程 | 相同时段不重复计时、资源不重复结算 |
| W03 | 确定过程 | 无新情况不反复调用模型重做决定 |
| W04 | 商路中断 | 运输、库存与后续影响符合依赖和资源规则 |
| W05 | 长时间跳转 | 不漏关键中间节点，介入节点按规则处理 |
| W06 | 原著前提改变 | 不硬播失去前提的后续事件 |
| W07 | 个人决策缺口 | 明确待决定，不把第三模块暗中并入 |
| W08 | 远近精度转换 | 已知历史不改写，跨地区不重复结算 |
| W09 | 信息传播 | 地区收到消息不自动等于全体角色知情 |
| W10 | 重试/取消/过期 | 沿用总控规则，不污染正式状态 |
| W11 | 有界推演 | 不无限展开因果或循环追加任务 |
| W12 | 呈现隔离 | 玩家正文不默认泄露后台变化 |

以上均未执行。后续分别记录规则测试、真实酒馆运行和人工试玩证据；测试通过不能替代用户接受。
