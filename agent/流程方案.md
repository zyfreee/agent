# 系统协同流程方案

版本：v1.0（设计基线）
日期：2026-10-21
状态：用户同意保存。仅设计，未实现、未接入插件或数据库、未做真实 SillyTavern 测试。

## 1. 目标

把已经确认的各功能连成一轮可执行的游玩流程，让玩家行动、NPC决定、世界过程和后续故事彼此产生真实影响，同时避免模块重复结算、越权决定或无限互相调用。

核心原则：

- 总控组织协作，但不替专业模块编造结果。
- 模块按实际需要调用，不要求每轮全部运行。
- 模块之间通过“新事实、有效知情、明确交接”相互影响，不让多个模型无边界互聊。
- 同一个结果只有一个负责模块；其他模块引用它，不重复计算。
- 候选结果不是正式历史；由总控协调外部插件或数据库完成正式保存。
- 玩家需要作决定时停下来，不替玩家继续行动。

## 2. 已纳入流程的组成

| 组成 | 主要职责 |
| --- | --- |
| 总控 | 识别本轮任务、安排依赖、控制预算、检查冲突、协调保存和异常恢复 |
| 原著资料 | 按需提供原著事实、版本、证据与缺失，不推演本局 |
| NPC独立互动与自主决策 | 处理指定NPC交流、意愿、计划及行动意图，不宣布执行成功 |
| 行动结算 | 检查一次明确行动的条件，计算直接结果、代价与耗时 |
| 玩家影响与世界演变 | 检查已确认事实如何改变任务、故事线、地点和势力条件 |
| 世界运转 | 在新条件下推进时间、资源、公共过程、既定计划和消息传播 |
| 主生成环节 | 根据核准结果生成玩家可见正文，不另设叙述Agent |
| 外部插件/数据库 | 保存正式状态、历史、计划和待处理事项；具体产品及能力待定 |
| 交互界面与运行反馈 | 展示可见状态、操作入口、处理进度和错误，不另存第二套状态 |

第七“状态与长期记忆Agent”已经删除，不能借本流程恢复。正式存储虽然交给外部插件或数据库，但总控仍需处理版本、提交结果和保存失败，不能假定外部工具天然具备分支、回退、知情隔离或成套提交能力。

## 3. 总体关系

```text
玩家输入／游戏时间推进／已有计划到期
                    ↓
                 【总控】
        读取本局数据，识别本轮处理范围
                    ↓
             按实际依赖组织协作

原著资料 ──依据──→ NPC决策／行动结算／世界演变／世界运转
                         │
NPC决策 ──行动意图──────→ 行动结算
                         │
行动结算 ──直接结果──────→ 世界演变
                         │             ↕ 有条件交接
                         └──────────→ 世界运转
                                           │
                                 新情况需要人物选择
                                           ↓
                                        NPC决策

                    ↓
         汇总一致的本轮候选及后续事项
                    ↓
        主生成环节写正文并检查重要偏差
                    ↓
       总控协调外部插件／数据库正式保存
                    ↓
          展示正文、状态及运行反馈
```

图中箭头表示允许交接，不代表每轮全部调用，也不代表每条箭头都需要单独模型请求。

## 4. 一轮完整流程

### FLOW-01 识别本轮请求

总控接收自然语言、界面操作、游戏时间推进或已有计划到期事件，先区分：

- 查询：如查看材料数量，能够可靠读取时直接回答；
- 交流或询问：如询问NPC是否愿意带路，不自动变成执行；
- 明确行动：如使用药物，进入行动结算；
- 时间推进或到期事项：先更新应当发生的持续过程，再处理新请求。

现实中的模型等待时间不等于游戏时间。请求有重大歧义时停下澄清，不擅自补成玩家行动。

### FLOW-02 读取并筛选必要信息

总控从外部存储读取当前会话、分支、状态版本、相关人物、过程和待处理事项。确实需要原著依据时，才向原著资料模块查询。

不同模块只获得完成职责所需的信息：

- NPC模块获得该人物实际知道的信息、目标、处境与权限；
- 行动结算获得执行所需条件、资源和规则；
- 世界运转获得相关时间、地区、资源和既有过程；
- 世界演变获得已确认事实及相关任务、故事线、地点和势力依赖。

不能把后台秘密全部交给NPC，再要求模型假装不知道。可独立的资料读取可以并行；存在前后依赖的处理必须等待上一步结果。

### FLOW-03 必要时先让NPC作决定

当问题涉及NPC是否愿意、选择哪种意图或是否调整计划时，先交NPC模块处理。

输出可以是接受、拒绝、询问、提出条件、等待、继续原计划或行动意图。NPC决定想做什么不等于已经成功。若需要玩家接受条件或回应，本轮停在玩家决定之前。

不涉及NPC选择的明确行动直接跳过本步。没有新事实、到期节点或条件变化时，不重复让NPC重新决定。

### FLOW-04 结算明确行动

行动结算模块检查行动条件，输出能否执行、直接结果、代价、耗时、阶段和中断点。

例如“决定查看断桥”属于NPC意图；能否出发、到达哪里、花费多久及途中直接结果属于执行流程。长行动只推进到必要节点，不一口气宣布全部完成。

同一操作的重试不得重复扣除资源或偷换随机结果。查询可行性不能被当作已经执行。

### FLOW-05 调整后续条件并推进世界

已确认的行动或事件可能改变后续前提：

- 玩家影响与世界演变模块检查任务、故事线、地点、势力及相关过程需要怎样调整；
- 世界运转模块在确认后的新条件下推进时间、资源、公共活动、既定计划和消息传播。

二者按真实因果顺序协作：

- 玩家行动先改变前提时，可以先检查影响，再推进过程；
- 时间推进先产生世界变化时，可以先运行世界过程，再检查故事线是否仍适用。

世界演变不预扣未来库存；世界运转不重复设计相同任务分支。世界自身造成的变化不能伪称玩家影响。

### FLOW-06 新情况需要选择时再请求NPC

世界过程可能产生新的NPC决策需求，例如道路中断后，队长要决定等待、返回、调查或请求玩家协助。

再次调用NPC模块必须同时满足：

1. 确实出现新的相关事实、到期节点或条件变化；
2. 该NPC已经通过有效渠道获知情况；
3. 仍在本轮范围和预算内。

新决定若产生明确行动，再按依赖交给行动结算和世界过程。若要等待未来时间、消息或玩家回应，就保存后续条件并结束本轮，不把整条未来一次演完。

### FLOW-07 汇总候选并检查一致性

总控汇总本轮候选事实、人物决定、行动结果、世界变化及待处理事项，检查：

- 状态版本是否仍有效；
- 时间、资源和权限是否一致；
- 是否重复处理同一来源事件；
- 是否把推测当成事实；
- 是否泄露不应公开的信息；
- 是否存在相互依赖却只完成一半的结果；
- 是否越过玩家必须回应的节点。

无法形成一致结果时暂停、失败或返回待决定，不为了给出正文而拼成矛盾历史。

### FLOW-08 生成玩家可见正文

主生成环节只根据核准候选和玩家可知范围写正文。可以补充不改变玩法的表达细节，但不能新增物品、伤势、承诺、成功结果或玩家行动。

正文若产生新的重要事实，必须退回相应检查，不能边写边偷偷生效。模型内部思考不作为交付内容。

### FLOW-09 正式保存并反馈

总控协调外部插件或数据库保存正式事实、人物计划、过程进度、后续触发条件及必要正文记录。保存成功后，界面才显示“已完成并保存”。

必须区分：

- 模型生成完毕；
- 候选检查通过；
- 正式保存成功；
- 保存结果不确定；
- 明确失败且未生效。

若外部存储不支持需要的成套提交或回退，应在接入设计中提供可验证的替代流程，不能只凭数据库存在就声称安全。

## 5. 防止无限循环

### RULE-01 同一变化只处理一次

每项重要变化关联来源事件、处理标识、负责模块和已处理范围。同一次断桥不能反复触发相同发现，也不能在多个模块重复扣资源。

### RULE-02 没有新事实就不重新决策

NPC已经决定等待时，没有新消息、条件变化或到期节点，就延续原计划，不再次调用模型随机变卦。

### RULE-03 未来后果留到生效时检查

“可能三天后缺货”不等于现在缺货。保存生效条件和下一处理节点，到时依据有效状态核验。

### RULE-04 每轮有范围和预算

本轮处理对象、连锁层数、模型调用、重试和耗时均应有上限，具体数值后续用样本确定。达到上限时报告未处理事项，不能宣称全世界已经更新。

必须一起成立的结果不能为了赶在预算内被拆成矛盾提交。超出范围的未来事项可以排队，不继续递归展开。

## 6. 典型场景

玩家对运输队员说：“前面的桥断了，别继续走。”

1. 总控判断这是告知消息，不是命令全队已经改道。
2. 筛选运输队员实际知道的内容和权限。
3. NPC模块判断其报告、查证、质疑或暂缓的意图。
4. 实际传话、查看等动作交给行动结算。
5. 世界运转推进耗时，并确认消息实际传到谁。
6. 有权的队长获知后，NPC模块再形成等待、调查或绕路等意图。
7. 世界演变检查运输任务、交付安排和相关故事线怎样调整。
8. 世界运转按已确认的新计划继续，但不保证行动自动成功。
9. 若队长请求玩家带路，本轮停在邀请，不能替玩家接受。
10. 主生成环节呈现玩家可知内容；保存成功后界面显示正式变化。

断桥真假、消息收到、是否相信、人物决定、行动执行和后续影响分别处理，不能一句话跳成“全队相信、成功绕路、所有人感激玩家”。

## 7. 待执行验收

1. 简单查询不误触整条Agent流程。
2. 询问不会自动变成执行，玩家决定节点会暂停。
3. NPC输入不含其未知后台秘密。
4. NPC意图不会直接当成行动成功。
5. 行动直接结果、世界过程和跨系统影响不重复结算。
6. 世界变化能触发必要的NPC重新决策，但无新事实时不会反复调用。
7. 条件性未来影响不会提前成为事实。
8. 同一来源事件只处理一次，重试不重复扣除或重抽。
9. 达到预算上限会保留后续事项并报告未处理范围。
10. 正文不改写核准结果或替玩家行动。
11. 保存失败、保存不确定和正式成功可以区分。
12. 切换分支或状态版本后，旧候选不能污染当前历史。
13. 一个完整样例可追溯每一步由哪个模块负责及为何触发。
