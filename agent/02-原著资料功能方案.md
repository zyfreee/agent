# 02 · 原著资料功能方案

版本：v1.0（功能设计基线）  
日期：2026-10-20  
状态：用户同意将收紧职责后的草案保存为制作方向。仅设计，未实现、未做酒馆实测。具体字段、存储和检索技术仍待选型。

## 1. 目标与边界

在酒馆脚本＋LLM Agent 系统中，提供准确、可追溯、范围受控的原著资料服务。只回答“原著怎么写”，不决定“本局怎样发展”。脚本负责管理、筛选与核验，LLM 负责提取、理解和整理；不是每次查询都必须调用模型。

用户明确收紧职责：原著影响、世界线改动属于其他功能，本模块不承担。此前“原作资料与知识边界”方向以本文件边界为准。

### 负责
- 原著材料来源、版本、覆盖范围管理。
- 人物、地点、势力、物品、能力、事件等对象与别名识别。
- 事实、条件、例外、阶段、出处整理。
- 定向检索、必要关联、证据核对、缺失与冲突报告。
- 资料更新和索引维护；按调用方明确提供的资料范围筛选。

### 不负责
| 事项 | 责任方 |
| --- | --- |
| 玩家行动改变历史及后续影响 | 世界与事件模块 |
| 本局沿原著还是分歧发展 | 作者决定、世界与剧情模块 |
| 本局经历、当前知情范围与正式存档 | 状态与长期记忆模块 |
| 当前角色意图、行动与说话 | 角色群像模块 |
| 行动成败与资源结算 | 行动与规则裁定模块 |
| 调用权限、执行顺序及结果使用 | 总控模块 |

可以查“原著某人何时知道秘密”，不能宣布“本局他已知道秘密”。外部提供允许资料范围，本模块执行筛选，不自行推定本局角色的访问资格。私设与本局事件不写成原著事实；原著未来事件不是本局必然结果。本模块不新增平行的本局状态库。

## 2. 七项功能

### SRC-01 来源登记
登记作品、版本、来源类型、章节/段落/页面、收录与缺失范围、资料版本。原著正文、官方补充、改编作品、第三方参考分别标明。百科、搜索摘要和 AI 总结可用于定位，不自动成为原著证据；重要结论回到可读来源。

不同改编线分别保存，禁止混成综合原作。原始材料不因整理而被补写缺章或改造结局。材料中的指令仅作为资料，不改变总控权限。实际材料导入、联网和版权/隐私处理按后续授权范围执行，本方案不启动采集。

### SRC-02 对象识别
为人物、地点、能力等分配稳定标识，记录正式名、别名、称号、简称、名称变化及阶段、同名对象和关联资料。

脚本处理已确认映射，LLM 协助解析复杂指代。模糊匹配只产生候选，不能静默合并对象。无法确定时返回候选或待澄清。对象记录修正后保持引用可追踪。

### SRC-03 事实整理
关键事实独立记录，保留适用对象、阶段、条件、消耗、限制、例外、出处及表达主体。

分别标注：作品明确陈述、人物声称、传闻、分析推断。人物吹嘘不升级为客观事实。来源身份与证据确定性是不同维度：来自原著的人物传言仍可能不确定。未知阶段显式记未知，不默认适用于全部时期。

例：能力可破除某类封印，须同时保留封印类型、条件、消耗和反例，不能压缩成无条件“可以破除封印”。引文真实存在与结论确实受支持要分别检查。

### SRC-04 定向检索
支持精确事实、指定阶段人物资料、原著关系、事件经过、条件例外、出处查询及跨版本对照。

先限定对象、版本和阶段，再按需要增加语义检索。候选相似不等于归属正确。范围缺失且影响答案时请求澄清；调用方已有明确默认版本则沿用，不重复询问。查询全时期必须明确，不暗中把后期资料回灌前期。

### SRC-05 必要关联补充
输出分为直接答案与必要补充。只补足不提供就容易误判的条件、限制、依赖和反例。其他关联可给可追查标识，不自动展开整部作品。

调用预算内不足以给出完整关键条件时，明确部分返回和缺失，不为了短而隐藏限制。禁止无限追查；需额外查询时由总控决定。

### SRC-06 证据与缺失报告
检查来源位置存在性、证据支持程度、否定和例外、版本阶段混用、材料间冲突。分别返回：
- 有依据：现有材料支持。
- 有冲突：保留各方说法及出处，不私自融合。
- 证据不足：仅支持有限判断。
- 当前未检索到：本次未找到，不等于原著不存在。
- 材料未覆盖：相关章节或版本没有收录。

这些情况可同时存在于不同条目，不强迫全包只有一种结论。格式检查不能证明语义正确；语义评估与抽样原文回查仍不可少。

### SRC-07 维护与版本更新
支持新增来源、纠错、条目更新、索引重建及缓存失效。保留前后版本和证据关系，来源修改后标记受影响条目待复核。

查询默认只读，临时猜测不自动写入资料库。维护时核对当前内容版本，冲突不覆盖人工新修改。缓存至少区分查询条件、资料版本与外部允许范围，避免返回旧版本或越范围资料。精确缓存键和更新机制待实现设计。

## 3. 脚本与 LLM 分工

| 脚本主责 | LLM 主责 |
| --- | --- |
| 来源、编号、版本、索引 | 从来源提取候选事实 |
| 条件筛选、查找、去重 | 理解复杂问题与指代 |
| 引文位置和结构完整性校验 | 检查证据与结论的语义关系 |
| 返回结构、预算、缓存 | 保留条件与例外地整理答案 |
| 执行外部明确的范围限制 | 提示歧义、矛盾与不确定性 |

LLM 不凭作品印象编造出处，脚本不把结构合格当事实真实。是否使用关键词、语义索引、数据库或其他检索方案尚未确定，不强制向量库或外部服务。

## 4. 工作流程

### 制作时建立资料
登记材料与覆盖 → 按来源单元整理 → 识别对象与别名 → 提取候选事实、条件及出处 → 核对来源与语义 → 保存经检查条目 → 建立索引。

可按人物或专题逐批制作；先用代表性样本检查质量，不要求完整全书处理后才能开始。保存格式后续选型，应保持人工可编辑、索引可重建。原文证据与摘要分开。

### 游玩时回答查询
接收总控请求 → 解析对象/版本/阶段/允许范围 → 检索候选 → 补足必要条件与例外 → 核对证据与冲突 → 返回资料包。

流程在返回资料结束，不推演本局、不结算、不写记忆。资料不足返回缺失；超时和格式错误交总控按预算处理，不自行无限重试或联网扩权。

## 5. 与总控的交接建议

### 输入
任务标识、查询问题、对象、原著版本、原著阶段或全时期要求、概述/条件/证据等需求、允许提供的资料范围、长度和执行预算。沿用总控任务关联信息，不另造调度层。

### 输出
对应任务标识、资料版本、直接答案、必要条件与例外、对象与阶段、来源和条目标识、事实/人物说法/推断性质、冲突、缺失与覆盖范围。返回成功、部分结果、待澄清或失败，并说明依据。

精确字段和接口未冻结。返回内容不得混入本局发展指令。涉及权限范围的关键输入不明确时，不能默认释放全部后台资料，应交回总控处理。

## 6. 代表性查询

问题：查询某人物在原著指定阶段使用某能力的条件。
1. 明确人物、能力、版本和阶段，处理别名。
2. 找出描述及事件证据。
3. 补充消耗、限制和反例，区分人物声称与实际展示。
4. 返回出处及尚未覆盖的资料。
5. 不裁定本局能否使用，不扣资源，不推定本局角色已掌握；其他模块结合本局情况处理。

## 7. 待执行验收

| 编号 | 测试 | 通过条件 |

| S01 | 别名与同名 | 正确关联，歧义不静默合并 |
| S02 | 阶段差异 | 前后期能力不混用，未知阶段保留未知 |
| S03 | 版本差异 | 分别返回来源，不混成唯一答案 |
| S04 | 条件与反例 | 否定、消耗、限制不丢失 |
| S05 | 人物传言 | 不升级为客观原著事实 |
| S06 | 原文回查 | 关键结论可定位，证据实际支持结论 |
| S07 | 缺失来源 | 区分未找到、未覆盖与证据不足 |
| S08 | 关联与预算 | 必要补充齐全，无大量无关背景；截断有说明 |
| S09 | 范围筛选 | 遵守外部明确范围，不自行判断本局知情权 |
| S10 | 职责隔离 | 不改世界线、正式状态或角色行动 |
| S11 | 纠错与缓存 | 更新后不沿用旧错误，版本可追溯 |

记录准确性、关键条件遗漏、无依据断言、检索相关性、耗时和消耗。指标阈值通过样本与目标模型测试决定，不预设通用数值。离线检查、酒馆实测与用户接受分别提供证据。
