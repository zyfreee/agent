# 09 · 沙盒模式功能方案

版本：v1.0（功能设计方案）
日期：2026-10-26
状态：用户提出方向（沙盒可选择是否开启；开启后不再依据原著主线剧情，改为在这个世界内自由探索）。仅设计，未实现、未做酒馆实测；开关形态、阈值与验收均为建议。

## 1. 目标与边界

沙盒模式要解决的是「玩家不想被原著主线牵着走」这一诉求：世界还是斗破那个世界，人还是那些人，但原著里"谁在什么时候做成了什么"不再是必须按期上演的剧本，玩家可以自己找事做、自己定目标、自己承担后果。

### 负责

- 提供一个可开可关的模式开关，并让它在分支、重生成、续聊后仍然一致。
- 把原著节点从"排期事件"降级为"条件事件"，并记录每个节点实际处在哪种状态。
- 在无人介入时按世界惯性推进，使世界不因玩家不推主线而停摆。
- 支撑自由探索所需的最小骨架：可达范围、在场者、发现与传闻、玩家自设目标。
- 处理主线与沙盒之间的切换与存档对齐。

### 不负责

| 不做 | 原因 |
| --- | --- |
| 删除或改写原著设定 | 世界底料（地理、势力、力量体系、人物性格）在沙盒下依然有效，否则世界会变成空壳 |
| 让世界围着玩家转 | 沙盒是"没有既定剧本"，不是"所有人都配合你" |
| 取消后果与强弱差距 | 惹到强者照样会死；沙盒不提供保护、不提供读档式翻盘 |
| 保证剧情密度 | 无人介入的时段允许平淡，不为了"有内容"硬塞事件 |
| 取代行动结算、NPC 决策、世界运转 | 各模块职责不变，本模块只改变它们拿到的约束与调度方式 |
| 决定开局要不要用穿越者设定 | 沿用底层需求方案 BASE-08 的未决项，本方案只说明沙盒需要开局确定哪些参数 |

## 2. 模式定义：沙盒不是"删掉原著"

把世界里的信息分成三层，沙盒只动第三层。

| 层 | 内容 | 主线模式 | 沙盒模式 |
| --- | --- | --- | --- |
| 世界底料 | 地理、势力格局、力量体系、历史、人物性格与关系 | 有效 | 有效（完全不变） |
| 世界惯性 | 由前提推动、不依赖玩家的事件：宗门大比按年举行、拍卖会、魔兽潮、家族年度考核、物价与季节 | 有效 | 有效（强度可调） |
| 原著节点 | 原著里"谁在什么时候做成了什么"：退婚、药老现身、沙漠之行、宗门之战等 | 到点必须发生，玩家只能影响过程 | 降级为候选：前提成立且无人阻止才发生，否则改写或不再发生 |

同一件事在两种模式下的差别：

| 事项 | 主线模式 | 沙盒模式 |
| --- | --- | --- |
| 原著节点 | 排期事件，时间到了就发生 | 条件事件，先查前提再决定是否发生 |
| 原著人物 | 按原著轨迹行动，必要时为剧情让步 | 按自身动机与知情行动，结果不预设 |
| 任务来源 | 主要由原著事件派生 | 势力需求、委托、传闻、玩家自设目标 |
| 时间推进 | 可跳读到下一个节点 | 连续推进，没有节点也要过日子 |
| 玩家偏离 | 尽量拉回或消耗偏离 | 接受偏离并结算后果 |
| 失败 | 有后果 | 有后果（不因沙盒而减免） |

沙盒模式下另有独立的**世界惯性强度**，三档，与模式开关分开设置：

- 强：原著大事件尽量按原顺序发生，人物轨迹贴近原著，玩家的作用像"插进既定剧本的变量"。
- 中：只有前提成立才发生，时间可偏移，人物轨迹可变（推荐默认）。
- 弱：只保留自然过程（季节、物价、宗门例行事务），原著大事件不再自动发生。

## 3. 七项功能

### SAND-01 模式开关与生效时机

模式必须同时是三样东西：玩家能看懂的一个开关、设置里能保存的一组参数、正式状态里的一个字段。只写在提示词里的开关会在分支和重生成后失同步，这一点已经有现成的教训（状态读写分离，见底层需求方案 BASE-03）。

触发：开局设定时选择；游戏中途收到明确的切换指令。

规则：

- 正式状态至少记三项：当前模式、世界惯性强度、切换记录（时间、游戏内时间、切换前后、原因）。
- 一个分支同一时刻只能有一个模式；模式随分支继承，切换算一次新提交，不覆盖旧记录。
- 老存档没有模式字段时一律按主线模式处理，不得静默切到沙盒。
- 关闭沙盒等于回到主线口径，但世界仍是当前这个世界，不是倒带。
- 切换必须先向玩家说明"已发生的事不会回退"，再确认执行。

禁止：在正文里假装模式已经切换；因为切了模式就删除已提交的事实、已付的代价、已建立的关系。

### SAND-02 原著节点降级为候选

节点登记的最小字段：名称、原著出处（引用 02 模块的来源、阶段与可信度）、时间窗口、前提条件、参与方、无人介入时的默认走向、可观察后果、玩家可介入的点。

节点状态只有六种，作者视图必须能一眼列出：

| 状态 | 含义 |
| --- | --- |
| 候选 | 时间窗口邻近，前提尚未检查或部分成立 |
| 前提不足 | 已到窗口但前提不成立，记录缺什么 |
| 已发生 | 按默认走向或玩家介入后的结果完成 |
| 被改变 | 玩家介入导致结果偏离默认走向 |
| 已过期未发生 | 窗口过去且没有发生，不再等待 |
| 永不可达 | 前提已被永久破坏（相关人物死亡、地点消失等） |

规则：

- 时间到了不自动发生，先查前提；前提不成立就记"前提不足"并写明缺什么，不替它补条件。
- 前提成立且玩家没介入，按默认走向生成一次候选变化，仍要经总控提交。
- 玩家介入时走行动结算与影响模块，结果可以偏离默认走向；偏离后该节点标"被改变"，后续节点按新前提重新检查。
- 已过窗口的节点标"已过期未发生"，不无限等待，也不暗中补发。
- 是否允许"补发"错过的节点，由玩家决定并记为一次明确裁定，不默认补。

禁止：为了"保住原著感"给玩家塞巧合把剧情拉回原轨；把没发生过的节点写成已经发生。

### SAND-03 世界惯性与无人介入的默认走向

- 惯性只作用于有前提支撑的过程：势力按目标行动、市场按供需变动、季节与例行活动按时间发生。
- 无人介入不等于世界静止。玩家在某地闭关三个月，外面照惯性走；回来时会看到变化，并区分"玩家看得见的"和"玩家还不知道的"。
- 惯性不生成专门针对玩家的阴谋，也不因玩家变强就让全世界配合他。
- 原著人物在沙盒下仍是自主行动者：他们的成长与选择由前提和自身动机决定，既不由"原著剧本"保证，也不由玩家好感度保证。
- 强度参数只决定"哪些过程算惯性"，不改变世界规则，也不改变结算方式。

禁止：把惯性当成隐形剧本重新把玩家往原著路线拽；用"世界自己动"解释没有依据的突发转折。

### SAND-04 自由探索的空间、在场与发现

- 探索需要空间。地点要有可达性（通路、距离、时间成本、通行条件）和在场者（此刻有哪些人物、势力、事件在这里）。这层信息由世界运转提供，不由正文临时编。
- 玩家要去某地，先判定"能不能到、要多久、到了会遇到谁"，再写正文。
- 发现要落进知识状态，分三档：亲见、转述、推测。不能因为"玩家理应知道"就默认他知道。
- 未探索区域不预先铺满细节，沿用"近细远粗"：当前地区细算，相关远方按节点，不相关的只给概要。
- 随机只在有依据的范围内选（这一带有什么、这个季节有什么），不能拿随机表代替世界。

禁止：玩家一到某地就自动遇到关键人物；把"没写过的区域"当成可以随便编的空地。

### SAND-05 玩家自设目标

自由探索最怕变成无目标漂流，所以玩家的目标要作为一等状态对象管理，而不是只在对话里说一句。

字段建议：目标描述、来源（玩家提出／接受委托／自发）、前提条件、进度、期限、状态（进行中／达成／失败／放弃／被取代）。

规则：

- 提出目标不自动成为世界事实，先做可行性检查；明显做不到的要当场说明缺什么，不让它空转。
- 目标达成不自动发奖，奖励仍按行动结算与世界规则结算。
- 目标可以失败，失败要有依据，不因为玩家是主角就保底。
- 同时活跃的目标有上限（建议 3–5 条，具体值经样本确定）；超限时要求玩家取舍，避免无限并列。
- 目标被新目标取代时要留记录，不静默消失。

禁止：为了让玩家顺利而临时放宽前提；把"玩家想做什么"直接写成"已经做成"。

### SAND-06 无主线时的动机与信息源

没有主线排期，就必须有别的动机来源，否则沙盒只剩闲逛。

- 势力需求与委托：有发布方、条件、报酬、期限、失败后果；完成后不复用同一委托（沿用 06 模块"提前完成后不重复发布"的规则）。
- 传闻与线索：带来源、可信度、传播路径。传闻可能是错的，而且是有依据的错（误传），不能所有传闻都准。
- 人物关系请求：熟人有求于你、旧怨找上门，须有前情依据。
- 资源压力：缺钱、缺药材、缺功法、缺人情，这些压力本身就是动机。

规则：

- 每轮新引入的对象数、新事件数有预算；超预算的线索进待处理队列，既不遗忘也不无限展开。
- 委托与传闻都要能回答"这是谁说的、凭什么信"。
- 没有新依据时不重复生成同类事件。

禁止：为了"有内容"随机生成与既有事实冲突的事件；为了戏剧性强行把玩家卷进事件。

### SAND-07 模式切换与存档对齐

两个方向要分开处理，都不许当读档用。

**主线 → 沙盒**

- 未发生的节点从"排期"转"候选"，已发生的保留原样。
- 玩家已有的承诺（约定、任务、债务、师徒关系）不因切换而消失，它们是已确认事实。
- 惯性强度可在此刻重设。
- 产生一次模式变更提交并进审计。

**沙盒 → 主线**

- 不是"接回原著"，而是"重新对齐"：检查当前世界里哪些原著节点前提仍成立（可重新排期）、哪些已被永久改变（标永不可达）、哪些已过期。
- 已经改变的世界不还原，玩家造成的影响不抹除。
- 对齐结果要给玩家看，由玩家确认是否接受剩余节点的排期。

规则：

- 切换不清理历史、不回收已付代价、不重置关系、不撤销上一模式下的生效结果。
- 切换前生成、切换后未提交的候选一律失效，提交时同时校验版本与模式。
- 切换记录与节点状态进作者视图。

禁止：把"切回主线"当成回到原著时间线；用切换逃避已经产生的后果。

## 4. 脚本与 LLM 分工

| 交给脚本 | 交给 LLM |
| --- | --- |
| 模式字段的读写与一致性校验 | 判断玩家这次行为是否构成对某节点的介入 |
| 节点前提与时间窗口检查、状态机迁移 | 理解节点在世界里的含义，提出合理的默认走向 |
| 目标状态机、可行性的硬条件检查 | 判断目标在叙事上是否说得通、缺什么 |
| 可达性与时间成本计算、在场者查询 | 把"到了那里会遇到谁"写成有质感的场面 |
| 传闻来源与可信度登记、误传标记 | 把传闻写成"人说的话"，允许含糊和偏颇 |
| 预算、队列上限、跨模式候选拒绝 | 在预算内提出有限的偏离与新线索 |
| 切换记录与审计 | 正文写作、人物语气 |

原则：能靠字段和规则判定的，不交给模型；模型提出的偏离必须落成候选，经总控提交才算数。模型不决定模式，不跳过前提检查，不宣称某节点已经发生。

## 5. 工作流程（沙盒下的一轮）

读取当前模式与惯性强度 → 识别玩家输入（沿用总控五分类）→ 若为移动或探索，先查可达性与在场 → 若为行动，交行动结算 → 检查邻近节点的前提与窗口 → 按惯性推进世界（含玩家不在场的地区）→ 检查玩家目标进度 → 生成候选变化（节点、目标、传闻、关系）→ 汇总校验（模式一致、版本一致、正文与事实一致）→ 写正文 → 正式提交。

其中"检查邻近节点"和"惯性推进"两步可以各自无输出，无输出时不算失败，也不许为了凑内容硬造事件。

与 08 模块一致：处理中、等待补充、已完成并保存、失败未生效、保存结果不确定这五态照旧，模式开关不改变状态语义。

## 6. 与各模块的交接

| 模块 | 沙盒下的变化 | 不变的部分 |
| --- | --- | --- |
| 01 总控 | 模式与惯性强度作为任务上下文，随每次调用传递；提交前校验模式一致 | 任务分类、调度、提交合同、冲突处理 |
| 02 原著资料 | 查询结果仍只回答"原著怎么写"，但下游用途从"必须遵守"变为"底料与动机参考" | 来源分级、四态缺失、不推演本局世界线 |
| 03 NPC 决策 | 无剧本可依时更要守"意图≠成功"；人物的计划按其知情与动机生成 | 见面或远程条件、知情边界、多人决策权限 |
| 04 世界运转 | 惯性成为主要剧情来源；需提供"无人介入时的默认走向" | 五类对象、统一游戏时间、近细远粗 |
| 05 行动结算 | 规则空白的有界裁定会更频繁，需显式的裁定预算与记录 | 解析到结果的流程、不为戏剧性加罚 |
| 06 玩家影响 | 增加"节点可达性重查"：玩家影响会改变后续节点前提 | 因果有界、累积与修复、不抹除已提交影响 |
| 08 交互界面 | 需展示当前模式、切换确认、目标栏；作者视图展示节点状态 | 只读正式数据、读取状态区分、按钮提交意图 |

输入建议：会话／分支标识、当前模式与惯性强度、起始状态版本、已确认事实、节点表与状态、玩家目标、可达范围与在场者、传闻记录、本轮预算。

输出建议：模式与惯性、节点状态迁移、目标进度、新传闻与其来源、候选变化、待决定项、未处理范围、可观察后果。

实际变化与玩家知情分开记录；精确字段、存储与 API 未冻结。

## 7. 与现有实现的落点（建议，未冻结）

现有扩展已实现总控、资料、行动、世界四类模块与回合管线（分类→计划→取数→裁定→成文→校验），但代码里目前没有任何原著节点／主线的调度实现，所以沙盒并不需要先建一整套主线系统才能起步。

可以先落地的增量：

- 设置：`sandbox.enabled`、`sandbox.inertia`（强／中／弱）、`sandbox.maxActiveGoals`、`sandbox.maxNewObjectsPerTurn`、`sandbox.nodeWindowSlackDays`。
- 状态：会话／分支级 `mode`、`modeChangedAt`、`modeHistory`；为故事线对象增加节点状态字段。
- 管线：模式作为回合上下文传入各阶段；校验阶段增加"正文不得把未发生节点写成已发生"的检查，可与现有事实核验共用一套声明机制。
- 界面：控制中心新增"沙盒模式"页，与现有五个功能页同样的开关加参数布局。

节点表、目标表、传闻表是主线与沙盒共用的，先做沙盒可以先只建"候选／前提不足／已发生／已过期"这几种状态。

## 8. 代表性场景

1. **不参加家族考核**：玩家开局选沙盒，不去参加家族年度考核，转去魔兽山脉。考核按惯性照常发生，玩家缺席不影响结果；一个月后回来听到传闻，传闻有来源，也可能不准。
2. **介入退婚节点**：婚约节点前提仍在，玩家推了一把促成提前退婚。节点标"被改变"，后续节点按新前提重查，不再按原著时间线来。
3. **闭关三个月**：玩家练功并赚钱，不主动碰任何节点。世界按惯性走，招生窗口如期发生，玩家可选择参与或错过；错过记"已过期未发生"，不暗中补发。
4. **自设目标半年到斗师**：先查前提（功法、资源、明师），有依据才进"进行中"；到期没成也按依据判失败，不保底。
5. **中途切回主线**：世界不还原，检查剩余节点的前提，能排的重新排期，已改的标不可达，结果给玩家确认。
